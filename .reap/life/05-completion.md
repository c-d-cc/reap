# 05 — Completion (gen-096-c749d5)

**Goal**: docs 사이트를 라우트별 정적 HTML 로 prerender 하고 로케일을 URL 로 분리한다
**Source backlog**: `docs-사이트가-페이지별-html-을-내지-않는다-prerender-가-필요하다.md` (consumed)
**결과**: 23 라우트 × 5 로케일 = **115 페이지**. 셸 하나(939 B)만 나가던 사이트가 페이지마다 실제 본문과
고유 `<title>` 을 낸다.

## Summary

### 무엇이 바뀌었나

`docs/` 는 여전히 Vite + React + wouter 이고 GitHub Pages 로 나간다. **추가된 것은 빌드 단계 하나**다 —
`vite build` 다음에 SSR 번들을 만들고 `react-dom/server` 로 전 라우트 × 전 로케일을 렌더해
`dist/public/<route>/index.html` 로 떨군다. 되돌리려면 `docs/package.json` 의 `build` 에서 두 단계를 빼면 된다.

로케일은 URL 로 나뉜다. **영어는 접두사가 없다** — `README*.md` 5개가 `https://reap.cc/docs/*` 를
직접 걸고(파일당 16개, 합 80개, distinct 15경로) 그 README 는 npm tarball 에 실린다. `/en/` 을 붙이면
이미 발행된 사본의 링크가 전부 죽는다.

라우트는 **23개 그대로**다. wouter 의 `<Router base="/ko">` 하나로 로케일을 분리했고 `<Link>` 가
`base + href` 로 링크를 만들어 사이드바·네비바가 자동으로 `/ko/…` 를 가리킨다 — 컴포넌트를 하나도
고치지 않았다. 115개 라우트를 선언하는 대안은 유지 대상만 5배로 늘린다.

### 신설

| 파일 | 역할 |
|---|---|
| `docs/src/routes.ts` | 라우트 매니페스트. **목록의 단일 소유자** — App.tsx 와 prerender 가 함께 읽는다 |
| `docs/src/i18n/locale-path.ts` | 로케일 ↔ URL. `parseLocalePath` / `localeHref` / `localeUrl` / `stripTrailingSlash` |
| `docs/src/entry-server.tsx` | 렌더·메타·sitemap·robots + 슬래시 불변식. **모든 판단이 여기** (`tsconfig` 가 `src/**` 만 본다) |
| `docs/scripts/prerender.mjs` | I/O 전용. origin 은 `docs/public/CNAME` 에서 읽어 주입 |
| `scripts/check-docs-prerender.sh` + `.mjs` | **층1** 게이트. `docs.yml` 에 배선 |
| `scripts/check-docs-live.sh` | **층2** 게이트. 배포본에 HTTP |

### 제거된 것

`localStorage` 로케일 기억과 `navigator.language` 자동 감지. URL 이 유일한 원천이 됐다.
부수적으로 기존 버그가 사라졌다 — `detectLocale` 의 저장값 검사가 `"de"` 를 빠뜨려
(`stored === "en" || "ko" || "ja" || "zh-CN"`) 독일어를 고른 사용자는 새로고침마다 잃고 있었다.

**UX 변경**: 한국어 브라우저로 `/` 에 오면 이제 영어가 뜬다. 셀렉터 한 번으로 전환되고, 내부 이동은
전부 wouter `<Link>` 라 한 번 바꾸면 세션 내내 유지된다. **fitness 판단 대상.**

## Lessons Learned

### 1. "측정할 수 없다"도 주장이고, 이 세대에서 **두 번** 거짓이었다

트레일링 슬래시를 "배포 전에는 알 수 없다"고 적었다. `curl -sI https://pages.github.com/versions` 한 줄이
답한다 — **301 to `/versions/`**. 층2 의 PASS 를 "원리상 관측 불가"라고 적었다.
`python3 -m http.server` 가 **2.0초**에 반증한다.

둘 다 그냥 틀린 게 아니라 **같은 측정**이었다. 리디렉션을 확인했으면 하이드레이션 결함이 그 자리에서
드러났다. 배포 전 404 를 근거로 삼은 것이 함정이었다 — **파일이 없어서 난 404 는 리디렉션 동작을
말해주지 않는다.** 내가 가진 증거가 그 질문에 답하지 못한다는 것을 알아채지 못했다.

### 2. 개수를 세는 검사는 **틀린 값으로 만족된다**

독립 검토가 게이트를 통과하는 결함 넷을 만들었다. 전부 같은 모양이었다:

- 4개 로케일이 전부 **영어 본문**(`<html lang>` 만 수정) — 로케일 **안에서** title 을 비교하니
  `/ko/` 밑의 영어 제목 23개도 "23 distinct" 다. canonical 은 전부 영어 URL 을 가리켰다 = 번역 색인 제외 지시
- hreflang **6개 전부 사이트 루트** — 개수는 여전히 6
- **JS 번들 삭제** — 정적으로는 다 렌더된다
- head 는 맞고 **본문이 전부 Hero** — 하드코딩 샘플 1개가 우연히 잡았다

내가 만든 negative 11개는 **게이트가 이미 덮는 단언만** 건드렸다. `hreflang` 을 **삭제**해봤지
**다른 값으로 바꿔**보지 않았다. **negative 를 설계할 때 "이 단언을 만족시키면서 틀릴 수 있는 값"을
따로 물어야 한다** — "이 단언을 깨는 법"이 아니라.

### 3. 검사기가 검사 대상과 기대값을 공유하면 아무것도 검사하지 않는다

`check-docs-prerender.mjs` 는 `entry-server.tsx` 를 **import 하지 않는다**. 기대 URL 을 파일의
디스크상 위치에서 재계산한다. import 했다면 틀린 `localeUrl` 이 자기 자신과 일치했을 것이다.
접두사 규칙 2줄은 **의도적으로 재서술**한다 — 그 규칙이 바뀌면 게이트가 **닫히는 방향**으로 깨진다.

목록(로케일)은 반대다. `types.ts` 하나가 소유하고 두 게이트가 읽는다. 층2 의 주석이
*"로케일 접두사도 소스에서 온다"* 고 **거짓 주장**하고 있었는데 — 세 줄 아래 하드코딩이 있었다 —
주석을 고치는 대신 **코드를 주장에 맞췄다**.

### 4. 파일을 읽는 검사로는 볼 수 없는 것이 있다

슬래시 불변식은 게이트가 아니라 **빌드**에 있다(`assertSlashInvariant`). 두 주소가 **같은 파일**을
받으므로 디스크를 아무리 읽어도 차이가 없다 — 차이는 브라우저가 렌더할 때만 나타난다.
빌드는 우회 불가능한 경로이고 비용은 **+4%**(3.673s vs 3.536s)다.

**검사를 어디에 둘지는 "무엇을 관측할 수 있는 자리인가"로 정한다.**

### 5. 고쳐 쓴 산문이 또 거짓이 된다 — 그리고 **자기 수정이 자기 문장을 낡게 만든다**

2차 요청 후 재독해로 4건을 더 찾았다. 그중 하나가 **내 수정이 만든 것**이다:
층2 헤더의 *"9 failures"* 가 **내가 침묵하던 분기를 말하게 만들어 14** 가 됐다. 사이트가 아니라
스크립트가 바뀐 것이다. 절 번호에도 구멍이 남았다(5 를 지우고 6 이 그대로).

**게이트의 출력을 바꾸면 그 출력에 대해 쓴 문장을 다시 읽어야 한다.** carrier 표식이 알려주지 않는
종류다 — grep 할 대상이 없고 두 번째 파일도 없다. 텍스트가 **바로 옆에 있어서** 건너뛴다.

### 6. 인계 문장 셋 중 둘이 틀렸고, 검토 지적 하나도 틀렸다

브리핑의 "라우트 25개"는 23이었고 "SSR 위험 2파일"은 **둘 다 위험하지 않았다** — 진짜 원인은
`i18n/context.tsx` 의 `useState(detectLocale)` 하나였고, 지목된 `ui/sidebar.tsx` 는 **어디서도
import 되지 않는 죽은 파일**이었다. 반대로 독립 검토가 *"`environment/summary.md` 가 627/331/44 로
낡았다"* 고 했는데 파일 실측은 **640/329/44** 로 정확했다.

**양쪽 다 실측이 갈랐다.** 검토자를 무조건 믿는 것과 인계를 무조건 믿는 것은 같은 실수다.

## Next Generation Hints

> adapt 에서 backlog 를 만들지 않는다. 아래는 **사용자가 고를 후보**다.

### 릴리즈와 함께 반드시 할 것

- **배포 직후 `bash scripts/check-docs-live.sh` 를 실제 reap.cc 에 돌린다.** 이 세대에서 PASS 를
  관측하지 못한 유일한 대상이고, 트레일링 슬래시의 실제 hop 수가 그 로그에 남는다
- **2차 독립 검토가 close 시점까지 미응답이었다.** 릴리즈 push 전에 받아볼 가치가 있다

### 사용자 판단이 필요한 것

- **`404.html`** — 지금 28,069 B 영어 홈이고 `canonical=https://reap.cc/`, OG=홈이다. 워크플로의
  `cp` 를 유지하라는 지시 때문이며 **미해결**. 권고: prerender 한 NotFound 를 쓰고 `cp` 제거
- **description 없는 페이지 20장** — `quick-start` · `core-concepts` · `release-notes` · `advanced`
  × 5 로케일. 페이지를 서술하는 기존 문자열이 없어 지어내지 않았다. 5개 언어로 쓸 것인가
- **로케일 자동 감지 제거** — 한국어 브라우저로 `/` 에 오면 영어. 되돌리려면 "루트에서만 1회
  리디렉션"이 대안이나 SEO 권고와 충돌한다

### 이 세대가 만든 빈틈

- **bash 게이트용 자동 회귀 하네스가 없다.** 이 세대가 게이트를 **둘 늘렸고** negative 20종을
  **손으로** 돌렸다. 다음 세대가 게이트를 고칠 때 자동 재확인되지 않는다. pending backlog
  `층2-게이트-판정부에-자동-회귀-검사가-없다` 와 같은 문제이며 이제 셋이다
- **활성 로케일 판정이 Tailwind 클래스 문자열(`text-primary font-medium`)에 의존한다.** 재스타일하면
  깨진다 — 닫히는 방향이지만 취약하다
- **실제 브라우저 하이드레이션은 여전히 미검증.** 저장소에 브라우저를 띄우는 것이 없다. 슬래시
  불변식은 **문자열 동일**을 보장할 뿐 React 가 조용히 하이드레이션한다는 관측이 아니다
