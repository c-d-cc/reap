## Outcome — 설계안

**구현하지 않았다.** 아래는 제안이고, 표면 하나는 사람이 정해야 한다.

### 1. 졸업 조건에 먼저 답한다 — harness의 `/loop`으로 대체되는가

**아니다. 그러나 대체하려 해서도 안 된다.**

`/loop`은 같은 세션을 깨운다 — 컨텍스트가 이어진다. ralph의 핵심은 **매 반복이 새 컨텍스트로 시작하고 기억은 파일에만 남는 것**이라 둘은 다른 물건이다.

그런데 REAP 입장에서 중요한 것은 **어느 쪽도 REAP의 것이 아니라는 사실**이다. 하나는 harness의 스케줄러이고 하나는 bash 한 줄이다. **REAP는 구동기를 고르지 말고, 어느 구동기 아래서도 맞게 돌아야 한다.** 이것이 이 설계의 첫째 결론이다.

### 2. REAP는 이미 ralph의 대부분이다

조사한 것과 이 리포를 대조하면 이렇게 갈린다.

| ralph가 필요로 하는 것 | REAP에 있는 것 |
|---|---|
| 매 반복 똑같이 먹이는 프롬프트 | **`reap ctx`** — genome·environment 요약·상태 줄. 이 리포에서 12KB, 매번 같은 순서 |
| 빌드·실행법 (`@AGENT.md`) | `environment/summary.md` |
| 매 반복 다시 읽는 명세 (`@specs/*`) | plan source + `map.md` + 상태 줄이 가리키는 경로 |
| 남은 일의 우선순위 (`@fix_plan.md`·`prd.json`) | milestone의 `tasks/` + `backlog/` |
| 새 컨텍스트를 잇는 기억 | 세대 기록 · `handoff.md` · `lessons.md` · git 히스토리 |
| **한 반복에 한 항목** | `evolve`의 "한 번의 편집으로 끝나는 일은 세대가 아니다", 한 세션 한 세대 |
| backpressure (테스트·타입) | `complete`의 커밋 규칙 · 독립 검증 절 · `doctor` |
| **멈춤** | **없다** |
| **반복 상한** | **없다** |

ralph가 임시로 만들어 쓰는 파일 기억이 **REAP의 설계 전체**다. 그러므로 `PROMPT.md`·`fix_plan.md`·`AGENT.md`에 대응하는 것을 새로 만들 이유가 없다 — 만들면 같은 것이 두 곳에 생긴다.

### 3. 그래서 REAP는 루프를 갖지 않는다

**구동기는 바깥이다.** bash 한 줄이든 harness의 `/loop`이든 CI 잡이든 상관없다. REAP가 더할 것은 **반복이 매번 읽을 것**과 **멈춰야 할 때를 말해 주는 사실**뿐이다.

이 선은 issue #34에서 이미 한 번 그었다 — *REAP는 상태를 적을 뿐 턴을 만들지 않는다.* ralph는 그 선을 넘지 않는다. **턴을 만드는 것은 셸이고, REAP는 그 턴이 제대로 착지하게 한다.**

### 4. 더할 것은 질의 하나다 — "지금 시작할 것이 있는가"

구동기가 알아야 하는 것은 하나다. **한 번 더 돌릴 것인가.** 그것을 판단이 아니라 **사실**로 답한다.

```
reap next        # 사람이 읽는 형태로 낸다
reap next -q     # 아무것도 안 내고 exit code만 — 있으면 0, 없으면 1
```

내는 것은 전부 이미 저장소에 있는 사실이다. **새 파일도 새 개념도 없다** — `run`이 실패한 자리가 거기였다.

| 내는 것 | 왜 사실인가 |
|---|---|
| 열린 세대와 그것이 이 세션에 묶였는지 | frontmatter와 `.session` |
| 열린 milestone과 focus 여부 | frontmatter |
| 소비되지 않은 backlog 항목 수 | 상태 필드 |
| 열린 flux 수 | 상태 필드 |
| `doctor` 결함 수 | 이미 확정적으로 검사한다 |

**멈추는 조건 둘은 REAP가 단정한다.**

- **`doctor` 결함이 있으면 멈춘다.** ralph가 backpressure라 부른 것이고, REAP에는 이미 있다. 결함 위에서 반복을 더 돌리면 그 위에 쌓는다
- **열린 세대가 이 세션의 것이 아니면 멈춘다.** 죽은 반복의 흔적이다

나머지는 구동기의 몫이다 — **반복 상한은 REAP가 갖지 않는다.** 그것은 프로젝트의 성질이 아니라 이번 실행의 성질이다.

### 5. 표면 — CLI냐 skill이냐 (**사람이 정할 것**)

**추천: 둘 다, 갈라서.** 근거는 REAP 자신의 원칙이다 — *확률에 의존하면 안 되는 것은 스크립트가 소유한다*.

| | 무엇을 | 왜 그쪽인가 |
|---|---|---|
| **CLI** `reap next` | 시작할 것이 있는가, 멈출 이유가 있는가 | 구동기가 exit code로 읽어야 한다. **셸이 판단을 물을 수는 없다** |
| **skill** `ralph` | 무엇을 `PROMPT.md`에 적는가, 왜 greenfield에서만 쓰는가, 한 반복에 한 항목인 이유 | 사람이 처음 세울 때 읽는 것이고 전부 판단이다 |

**한쪽만 두는 길의 대가.**

- **CLI만** — 구동기는 돌지만 사람이 `PROMPT.md`에 무엇을 적을지 모른다. 조사가 밝힌 실패 셋(구현된 것을 안 됐다고 가정·placeholder·검색 비결정성)을 아무도 안 알려준다
- **skill만** — 멈춤을 산문으로 설명해야 하고, 셸은 산문을 못 읽는다. 결국 사람이 `grep`으로 흉내 내고 그것이 조용히 틀린다

### 6. 이것이 issue #34에 답이 되는가

**된다. 그리고 `run`을 되살리지 않고 된다.**

#34의 공백은 *"한 항목을 닫은 뒤 다음으로 넘어갈 의무를 적어 둘 자리가 없다"*였다. `run`은 그 의무를 **저장**하려다 실패했다. `reap next`는 저장하지 않는다 — **매번 계산한다.** 남은 것이 저장소에 이미 있으므로 따로 적을 필요가 없었던 것이다.

그리고 #34의 진짜 근인(에이전트가 보고하면 턴이 끝난다)은 여전히 REAP 밖이다. 구동기가 그 자리를 맡는다.

### 7. 설계하다 드러난 위험 하나 — **자율 반복의 교착**

`evolve`는 *"열린 세대가 있으면 먼저 멈추고 사람에게 확인한다"*고 한다. 사람이 있을 때는 옳다. **구동기 아래서는 사람이 없다.**

반복이 세대를 열고 죽으면 다음 반복은 그 세대를 보고 멈춘다. 그리고 영원히 멈춰 있는다 — 확인해 줄 사람이 없기 때문이다.

**이것을 이번 설계에서 풀지 않았다.** 고르는 길이 셋이고 전부 규율을 바꾼다.

1. 구동기가 `--aborted`로 치우고 다음 반복을 돌린다 — 죽은 세대의 작업이 조용히 사라진다
2. `evolve`가 "구동기 아래서는 이어서 연다"를 갖는다 — REAP가 실행 형태를 알게 된다. 지금까지 피해 온 것이다
3. 멈춘 채로 두고 `doctor`가 보고한다 — 자율 실행이 사람을 기다리며 멈춘다. **가장 정직하지만 ralph의 값이 절반으로 준다**

**추천은 3이다.** 멈추는 것이 잘못된 것 위에 쌓는 것보다 낫고, ralph 원저자도 실패 시 사람의 `git reset`을 전제한다. 다만 이것은 판단이라 사람의 것이다.

## 사람이 정할 것 둘

1. **표면** — CLI `reap next` + skill `ralph` 둘 다인가(추천), 한쪽인가
2. **교착** — 열린 세대를 만난 자율 반복이 무엇을 하는가. 위 셋 중 3을 추천한다

## 하지 않기로 한 것

- **`PROMPT.md`에 대응하는 파일을 REAP에 두지 않는다.** `ctx`가 이미 그것이다
- **반복 상한을 REAP에 두지 않는다.** 이번 실행의 성질이지 프로젝트의 성질이 아니다
- **구동기를 REAP가 고르지 않는다.** bash든 `/loop`이든 CI든, 어느 쪽에서도 맞게 돌면 된다
- **새 저장 개념을 만들지 않는다.** `run`에서 세 세대를 잃고 배운 것이다
