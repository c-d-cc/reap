# Task 2.4 — `map.md` · skill · 훅 최종 갱신과 전체 검증

**처음 계획에서 마이그레이션이 빠지고 `map.md`가 들어왔다.** 원래 이 task가 "이 리포 마이그레이션"을 통째로 들고 있었는데, 그것이 각 task로 흩어졌다 — 코드를 옮긴 세대가 리포도 같이 옮긴다. 이유는 `gen-0012-exec`의 Dead Ends에 있다.

남은 것은 **앞의 셋이 다 선 뒤에야 할 수 있는 것**뿐이다.

## `map.md` — 이 task의 절반

`init`이 `.reap/map.md`를 놓는다. **각 폴더 계층이 무엇을 뜻하는지 그 파일 하나로 알 수 있어야 한다.**

규범은 [저장 구조](../../../../../docs/superpowers/specs/reap/03-storage.md)의 "`map.md` — 구조가 스스로를 설명한다"가 소유한다.

- 번들 템플릿 `map.md`를 더하고 `SEEDS`에 넣는다. **씨앗이므로 이미 있으면 덮어쓰지 않는다**
- 상태 줄이 `구조: .reap/map.md` 한 줄을 낸다. **통째로 싣지 않는다** — 주입은 한 번 늘리면 줄이기 어렵다
- 빈 파일이면 줄을 내지 않는다. 기억·idea 줄과 같은 규칙이다

**여기서 쓰는 이유는 앞의 셋이 다 서야 내용이 확정되기 때문이다.** 2.2 전에 쓰면 `gen-0001-exec` 형식의 파일 이름을 적게 되고, 2.3 전에 쓰면 fix 세대와 `archive/generations/`의 관계를 못 적는다.

내용이 담아야 할 것 — 3단이 무엇으로 갈리는지(하려는 것 / 하는 중 / 끝난 것) · 각 디렉토리에 무엇이 사는지 · 세대가 유형과 무관하게 한 곳에 쌓이고 소속은 frontmatter가 말한다는 것 · id 형식.

## 무엇이 참이어야 하는가

- 플러그인 skill과 훅이 새 경로·새 id·`cleanup`을 안다. `evolve`가 읽으라고 안내하는 경로가 실제로 존재한다
- `reap ctx`가 옛 경로를 하나도 내지 않는다
- 문서 안의 세대 id 인용이 전부 새 id를 가리킨다. `.reap/` · `docs/` · `plugin/` 전부. **옛 id → 새 id 매핑이 다음 세대가 찾을 수 있는 곳에 있다** (2.2가 남긴다)
- 새 세션을 열어 맥락이 정상 주입된다. **`reap`를 PATH에서 뺀 상태에서도 세션이 정상 시작한다** — invariant다

## 함정

`git mv`에 글롭을 주면 **하나가 실패할 때 전체가 취소된다.** `gen-0013-exec`이 추적 안 된 상태여서 같은 글롭의 `gen-0012-exec`까지 안 옮겨졌고, 에러 메시지는 실패한 것만 말했다. 옮긴 뒤 `ls`로 확인한다.

인용 치환은 기계적으로 하되 **단어 경계를 쓴다** — `gen-0001-exec`이 `exec-0012`의 접두사이기도 하다.
