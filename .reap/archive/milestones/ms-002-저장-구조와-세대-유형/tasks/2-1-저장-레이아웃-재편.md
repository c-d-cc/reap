# Task 2.1 — 저장 레이아웃 재편

규범은 [저장 구조](../../../../../docs/superpowers/specs/reap/03-storage.md)가 소유한다. 여기에는 무엇이 참이어야 하는지만 적는다.

## 바뀌는 것

```
.reap/plan/           →  .reap/vision/plan/
.reap/memory/         →  .reap/vision/memory/
.reap/milestones/     →  .reap/vision/milestones/
.reap/backlog/        →  .reap/life/backlog/
(신설)                 →  .reap/life/generations/
.reap/archive/<ms>/   →  .reap/archive/milestones/<ms>/
(신설)                 →  .reap/archive/generations/
```

`genome/` · `environment/` · `idea/` · `sequence/` · `hooks/` · `config.yml` · `templates/` · `.session`은 자리를 지킨다.

**세대는 milestone 디렉토리 안에 살지 않는다.** `milestones/<ms>/generations/`가 없어진다.

## 공개 인터페이스

`paths(root)`가 반환하는 필드 이름이 바뀐다. **경로 문자열을 이 함수 밖에서 조립하는 곳이 남아 있으면 안 된다** — 재편이 한 곳에서 끝나는지가 이 task의 실제 판정이다.

## 무엇이 참이어야 하는가

- `init`이 새 구조를 만든다. `life/generations/`와 `archive/` 둘 다 처음부터 있다
- **빈 디렉토리는 git이 추적하지 않는다.** 증분 1이 이것을 어떻게 다뤘는지 확인하고 같은 방식을 따른다 — 새로 늘어난 디렉토리에서 조용히 갈리면 안 된다
- 이미 `.reap/`가 있는 곳에서 `init`을 다시 돌려도 기존 파일을 덮어쓰지 않는다

## 함정

`store.ts`의 경로 상수를 바꾸면 테스트가 통과하는데 실제로는 옛 경로를 읽는 곳이 남을 수 있다 — 테스트가 `init`이 만든 것만 보기 때문이다. **`.reap` 문자열 리터럴이 `store.ts` 밖에 몇 개 있는지 먼저 센다.**
