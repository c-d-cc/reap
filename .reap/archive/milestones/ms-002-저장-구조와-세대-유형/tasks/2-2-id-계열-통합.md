# Task 2.2 — id 계열 통합

규범은 [id 체계](../../../../../docs/superpowers/specs/reap/03-storage.md)가 소유한다.

## 바뀌는 것

```
gen-0004-plan · gen-0001-exec · (fix-001)   →   gen-0001-plan · gen-0002-exec · gen-0003-fix
sequence/plan-generation.md              sequence/generation.md   (하나로)
sequence/exec-generation.md
```

**순번은 유형과 무관한 하나의 계열이다.** `gen-0001-plan` 다음이 `gen-0002-exec`일 수 있다.

## 공개 인터페이스

`Kind`가 줄어든다 — generation 유형 셋이 하나의 `generation`이 되고, plan/exec/fix는 kind가 아니라 **id 안의 값이자 frontmatter의 `type`**이다.

## 무엇이 참이어야 하는가

- `kindOf("gen-0002-exec")`가 generation을 낸다. `kindOf("gen-0002")`는 **낼 수 없다** — 유형이 id의 일부이므로 불완전한 id다
- `gen-0002-exec-token-rotation.md`에서 id는 `gen-0002-exec`, slug는 `token-rotation`이다. **id의 모양이 고정이라 이 경계가 결정적으로 갈린다** — `gen-\d{4}-(plan|exec|fix)`
- 레지스트리는 하나이고 여전히 append-only다. 유형이 달라도 같은 계열에서 번호를 받는다
- 네 자리를 넘겨도(`gen-10000-exec`) 형식이 깨지지 않는다. 정렬만 어긋난다
- 이름순 정렬이 발급순과 같다 (네 자리 안에서)

## 함정

지금 `kindOf`는 **첫 `-` 앞을 접두사로 보고** 계열을 정한다. `gen-0002-exec`에는 `-`가 둘이라 그 전제가 깨진다. 접두사 표를 그대로 두고 확장하려다 `gen`이 다른 것과 충돌하지 않는지만 보고 넘어가면, `gen-0002`(유형 없음)나 `gen-0002-foo`(모르는 유형)가 조용히 통과할 수 있다. **거부되어야 하는 것이 거부되는지를 테스트가 먼저 말하게 한다.**
