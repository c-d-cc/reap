# 3.4 — 로드맵과 spec 정합

증분 4에서 둘을 당겨왔고, 3.1~3.3이 문서 곳곳을 건드린다. **문서가 그것을 모른 채 남으면 다음 milestone이 옛 로드맵을 읽고 자른다.**

**증분 2 자체는 `gen-0022-plan`이 이미 내렸다** — 자른 것은 로드맵에 남기지 않는 것이 그 파일의 규칙이고, 왜 바뀌었는지는 머리말에 적혀 있다. 여기서 다시 하지 않는다.

## 손댈 곳

| 파일 | 무엇 |
|---|---|
| `09-roadmap.md` 증분 4 | `backlog`·`idea`가 `ms-003`으로 갔다. 남은 것은 `doctor`·`seq`·milestone 종료 흐름이다 |
| `environment/summary.md` | 명령 둘이 늘고 skill이 하나 준다. 매 세션 주입되므로 낡으면 매번 틀린 것을 읽힌다 |
| spec 전반 | 3.1~3.3이 만든 새 어긋남 |

## 함정

- **로드맵은 아직 안 자른 것만 담는다.** 자른 것은 `vision/milestones/`의 milestone이 된다(`09-roadmap.md` 머리말). 증분 2를 자른 뒤 로드맵에 그대로 두면 두 곳에 같은 것이 있게 된다 — `ms-001`·`ms-002`를 어떻게 처리했는지 보고 같게 한다
- **`gen-0021-fix`가 방금 spec 드리프트 셋을 고쳤다.** 그때 쓴 전수 검사(상대 링크 14개 · 백틱 안 리포 경로 7개)를 다시 돌린다. 3.1~3.3이 새 드리프트를 만들었을 수 있다
- **`environment/summary.md`도 매 세션 주입된다.** 명령이 둘 늘고 skill이 하나 줄면 여기도 낡는다

## 완료 판정

- 로드맵의 증분 2·4가 실제와 맞는다
- spec 링크·경로 전수 검사가 깨진 것 0을 낸다
- `environment/summary.md`가 지금 있는 명령과 skill 개수를 맞게 적는다
- `bun test` 통과 · `typecheck` 0 · `./tests/hook.test.sh` 통과
