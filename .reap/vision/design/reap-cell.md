## 0. 전제 `[확정 2026-08-21]`

이 설계는 다음 셋을 **확정 전제**로 삼는다. 결론이 아니라 전제이므로, 바꾸려면 여기부터 다시 연다.

| 전제 | 내용 |
|---|---|
| **단일 머신** | 모든 cell 이 한 머신 위에 있다. **네트워크 환경은 고려하지 않는다** |
| **단일 조직** | cell 들은 한 조직 안에 있다. 통치 경계는 조직 내부에서만 갈린다 |
| **다중 agent** | 실행 주체는 여럿이다. cell 하나에 대해서도 여럿일 수 있다 |

### 왜 이 전제가 정당한가

git 은 **기술 문제가 아니라 사회 문제의 해법**이었다 — 참여자가 서로 만날 수 없고, 파일시스템을 공유할 수 없고, 서로를 신뢰하지 않는다는 전제. 행위자가 한 머신 위의 agent 가 되면 **셋이 동시에 사라진다.**

그리고 **merge 는 기능이 아니라 분산의 세금**이다. 브랜치·머지는 "서로를 못 보면서 병렬로 일한다"에 대한 낙관적 동시성 제어이며, 파일시스템을 공유하면 비관적 제어가 가능해지고 충돌 해소 비용이 0 이 된다. REAP 의 `merge` lifecycle(detect→mate→merge→reconcile→3-way genome diff) 전체가 그 세금이다.

**단, 하중을 받는 것은 "단일 머신"이 아니라 "단일 SSOT" 다.** 둘은 서로를 함의하지 않는다 — 권위 있는 저장소 하나를 여러 머신이 써도 SSOT 이고(Piper/CitC, Perforce), 한 머신 위 두 worktree 는 이미 사본 둘이다. **단일 머신이 없애는 것은 네트워크이지 분기가 아니다.** 위 전제는 편의를 위한 범위 축소이며, 설계 원칙은 SSOT 쪽에 걸어야 한다.

### 이 전제가 없애는 것

| 대상 | 결과 |
|---|---|
| §6.7 채널 위치 | **닫힘** — 로컬 파일로 충분. 공유 미러 repo 불필요, write 권한·경합·가용성 문제 소멸 |
| §6.4 확인 시점 | **완화** — fetch 비용이 없다. 다만 "언제 보는가"의 규율은 남는다(§7.5) |
| §11-2 다중 머신 | **닫힘** — 범위 밖 |
| §11-3 블록체인 | **기각** — §10 참조 |
| §10 global registry 기각의 재검토 | **불필요** — 기각이 그대로 선다 |

### 이 전제가 **만드는** 것 — 동시성

분산을 걷어내면 조율 비용이 사라지는 대신 **동시 실행 주체 간 조정**이 새 문제로 올라온다. 공짜가 아니라 **문제의 교환**이다.

사람은 스스로 throttle 한다 — 두 파일을 동시에 타이핑할 수 없다. **agent 는 하지 않는다.** 빠르고, 많고, 서로를 보지 않는다.

**실제로 발생했다** (2026-08-21, 이 설계 대화 중): 한 세션이 `gen-095` 를 활성으로 알고 작업하는 동안 `current.yml` 은 이미 `gen-096` 이었고, **그 세션은 자기 세계관이 낡았다는 것을 알 수단이 없었다.** 분산 때문이 아니라 **단일 머신 + 공유 가변 상태**라서 일어났다.

→ **§7.5 로 등록.** 이 설계가 반드시 답해야 하는 항목이다.

## 1. 동기

REAP 은 **프로젝트 하나 = pipeline 하나**를 전제한다. `life/current.yml` 은 단일 활성 generation 을 담고, genome·vision·memory 는 그 하나의 pipeline 을 위해 존재한다.

대규모 조직에서 이 전제가 깨진다. 하나의 목표가 **서로 다른 저장소 · 서로 다른 팀 · 서로 다른 리듬**으로 갈라지는데 REAP 에는 그것을 표현할 수단이 없다. 증상은 둘이다:

- **generation 비대화** — 여러 저장소에 걸친 작업을 억지로 한 세대에 담는다
- **지식 파편화** — 하위 저장소를 REAP 밖에서 관리하고, 교훈이 서로에게 도달하지 않는다

## 2. 용어와 정의

### 2.1 왜 `tree` 가 아니라 `cell` 인가 `[확정]`

전신 문서는 `Tree` 였고, 그 문서 자신이 §11-4 에서 경고를 남겼다 — *"'Tree'라는 이름이 이미 답을 전제하고 있다."*

실제로 tree 는 틀렸다. 이유는 "공유 라이브러리가 다중 부모"여서가 **아니라**, tree 가 **관계의 종류가 하나라고 전제**하기 때문이다. 소유(누가 책임지나)와 의존(무엇이 무엇을 부수나)은 서로 다른 그래프이고 **허용되는 모양도 다르다**(§3.2).

`cell` 은:

- **막(membrane)과 내부**를 뜻한다 — 막이 곧 인터페이스이고, 내부는 불투명하며, 소통은 수용체·리간드로만 일어난다. provide/consume 이 문자 그대로 cell signaling 이다
- REAP 의 기존 은유(genome / generation / lineage / mutation / crossover / fitness / maturity)에 **외부에서 빌려온 게 아니라 원래 자리로** 들어간다
- **모양을 전제하지 않는다**

**은유를 더 밀지 말 것**: 모세포→딸세포의 genome 상속에 대응하는 단어는 lineage/descent 인데, REAP 은 `lineage` 를 세대 이력에 이미 쓴다. 충돌한다. `governs` 는 비은유적이지만 그대로 둔다.

### 2.2 Cell `[잠정 — 재정의 제안, 미승인]`

전신 문서와 이 문서 초판은 **Cell = `.reap/` 를 가진 저장소** 로 정의했다. §0 전제 아래에서는 이 정의가 약하다 — 저장이 균일해지면 저장소는 더 이상 무엇도 구분하지 않는다.

제안하는 재정의:

> **Cell = 통치(governance) 경계다.** 저장소가 하나인지 여럿인지, 어느 머신에 있는지는 **구현 세부**다.

근거: agentic 개발은 git 이 "repo" 하나로 묶어둔 세 축을 푼다.

| 축 | 왜 분산했었나 | 이 전제 아래 |
|---|---|---|
| **저장** | 각자 로컬에서 일해야 하니까 | **중앙화된다** |
| **동시성** | 서로 안 보이니 낙관적 merge | **형태가 바뀐다** — 비관적 제어가 가능해지고 **필요해진다** (§7.5) |
| **통치** | 접근제어 · 릴리즈 독립 · blast radius | **그대로 살아남는다** ← cell 이 붙잡는 축 |

통치 이유는 사람의 신체 제약이 사라져도 하나도 사라지지 않는다. 오히려 agent 는 **더 넓고 빠르게 읽으므로** 접근 제어가 더 중요해진다.

실무적으로는 여전히 **cell 하나 = `.reap/` 하나 = 저장소 하나**로 구현된다. 달라지는 것은 *왜* 그렇게 나누는가이며, 그 답이 §7.5(동시성 단위)를 결정한다.

- 자기 repo 와 자기 `.reap/` 를 독립적으로 소유한다
- **막 = 선언된 인터페이스.** cell 의 내부는 다른 cell 에게 불투명하다
- REAP 은 이 위에 **관측 · 전파 · 자기구속** layer 를 제공한다 (강제 layer 가 아니다 — §7)

### 2.3 merge 와의 차이 — 이 구분이 설계의 출발점 `[확정]`

| | merge | cell |
|---|---|---|
| 대상 | **같은** repo 의 병렬 브랜치 | **서로 다른** repo |
| 관계 | 수평 — 갈라졌다 합쳐짐 | 막을 사이에 둔 인접 |
| genome | 3-way diff 로 **교차** | `governs` 축에서만 **상속** |
| 종료 | 하나로 수렴 | 수렴하지 않음. 계속 병존 |
| 생명주기 | 하나의 lifecycle | **cell 마다 독립 lifecycle** |

merge 를 확장해 cell 을 만들 수 없다. merge 의 모든 단계가 "결국 하나가 된다"를 전제한다.

### 2.4 monorepo 와의 차이 `[확정]`

cell 은 **디렉토리 구조가 아니라 pipeline 구조**다. 판단 기준은 "저장소가 나뉘어 있는가"가 아니라 **"독립된 lifecycle 과 독립된 genome 이 필요한가"**.

## 3. 모델

### 3.1 노드 2종 · 엣지 3+1종 `[확정]`

```
노드:  Cell       — `.reap/` 를 소유한 저장소
       Interface  — 선언된 계약. 제공자 1개

원시 엣지:
  provides   Cell → Interface
  consumes   Cell → Interface
  governs    Cell → Cell        (상위 최대 1)

파생 엣지:
  depends-on = consumes ∘ provides⁻¹   ← 선언하지 않는다. 계산한다
```

**인터페이스가 엣지 속성이 아니라 노드인 것**이 이 모델의 핵심이다:

| | 인터페이스가 엣지 속성일 때 | 인터페이스가 노드일 때 |
|---|---|---|
| A↔B 상호 호출 | cell 레벨 순환 — 손 못 댐 | `A→api-B`, `B→api-A` 로 **분해.** 인터페이스 단위로 실제 순환인지 판정 가능 |
| 버전 | 붙일 자리 없음 | `consumes api-B@2` |
| 파손 범위 | "B를 언급하는 전부" | `consumes: api-B` 인 cell **정확히 그것** |
| 소유권 | 모호 | 제공자 1개. 선언이 제공자 repo 에 산다 |

**`depends-on` 은 원시 엣지가 아니다.** 선언이 아니므로 독립적으로 틀릴 수 없다.

**`relates-to` 는 폐기했다.** 초안에 있었으나 아무것도 흐르지 않는 엣지는 아무것도 뜻하지 않았다 (YAGNI).

### 3.2 엣지 타입별 법칙 `[확정]`

**전파가 있는 엣지에만 제약을 건다.**

| 엣지 | 허용 모양 | 흐르는 것 | 다중 부모 |
|---|---|---|---|
| `governs` | 단일 상위 (**비순환은 별도 검사** — 아래) | invariants·genome 상속, goal 배정 | **금지** |
| `provides` / `consumes` | 제약 없음 | 계약 | — |
| `depends-on` (파생) | **순환 허용** | impact | — |

**단일 부모는 비순환을 함의하지 않는다.** `A→B→C→A` 는 각자 상위가 1개여도 성립한다. 다만 판정이 싸다 — **조상 사슬을 위로 걸어 올라가다 자기를 다시 만나면 순환**이다. O(depth), 전역 그래프 불필요.

**`depends-on` 의 순환은 오류가 아니라 사실이다.** 빌드 시스템에서 순환이 치명적인 이유는 빌드 순서가 없어져서인데, REAP 은 빌드 파이프라인이 아니다. 엔터프라이즈에 순환 의존은 실제로 존재하고, REAP 의 역할은 금지가 아니라 **보고**다.

### 3.3 주소 지정 `[확정]`

정본 식별자는 **git remote URL**(+ 선택적 branch). 로컬 경로는 캐시로만 두고, 없으면 해석 실패가 아니라 "미해석 cell" 로 관측에서 제외하되 **그 수를 절대수로 보고한다**(§9).

### 3.4 전파 깊이 `[확정]`

**1-hop 고정.** 조부모 지식은 부모가 소화해서 내려보내고, 손자 결과는 부모가 요약해 올린다.

impact 에도 같은 규칙이 적용되며, **이건 싸서가 아니라 더 정확해서다**:

- 전역 그래프: A가 바뀜 → 의존 순회 → "C가 영향받음". **A가 무엇을 바꿨는지 모른 채 판정한다.** 과대 포함이 기본값
- 1-hop 사슬: A가 직접 소비자 B에게 알림 → **B가 "내 약속이 움직였나"를 스스로 판정** → 움직였을 때만 C로

**B의 계약이 실제로 움직였는지는 B만 안다.** 전역 그래프는 그 판정을 할 수 없다.

이건 이미 도는 프로토콜이다 — **semver 가 정확히 이것**이다. 제공자가 파손을 *선언*하고 소비자가 *계산*하지 않는다. npm 에 레지스트리가 있어도 **파손 의미는 레지스트리가 아니라 버전 문자열이 나른다.**

## 4. 인터페이스 `[미결 — 가장 큰 미지수]`

**확정된 것**:

- 제공자는 **정확히 1개**. 다중 제공자(재구현·로드밸런싱)는 다른 문제이며 보류
- 선언은 **제공자 repo 에 산다**. 소비자는 ID 로 참조한다
- **약속한 인터페이스는 prescriptive → genome 형태**다. 실제 구현된 표면은 descriptive → environment. **둘의 차이가 cell 스스로 감지 가능한 결함**이 된다 — "내가 약속한 걸 아직 제공하는가"
- 검증 가능성이 **종류마다 다르다.** `reap index` 로 확인되는 것(export 심볼)이 있고, 선언만 되는 것(HTTP API, 프로토콜, 파일 포맷)이 있다

**미결**:

1. **표현 형식** — 무엇을 어떤 스키마로 선언하는가 (심볼 / 엔드포인트 / 스키마 / 파일 포맷 / 이벤트)
2. **검증 가능 종류와 선언뿐인 종류를 타입에 어떻게 표기하는가.** 표기하지 않으면 "선언됐으니 맞겠지"가 된다
3. **버전과 은퇴 지점의 표기** — semver? SHA? 둘 다?

**이 셋이 §3(엣지) · §6(채널 항목 형식) · §7(핀 대상)을 다시 건드릴 수 있다.** 그래서 후속 절들이 이것에 종속된다.

## 5. 지식 전파 (`governs` 축) `[잠정]`

| 대상 | 전파? | 근거 |
|---|---|---|
| `genome/invariants.md` | **상속 (강제)** | 하위가 상위 invariant 를 어기면 관계가 성립하지 않음 |
| `genome/application.md` | 상속 (참조) | 아키텍처·컨벤션 공유. child 고유 항목 추가 가능 |
| `genome/evolution.md` | 상속 (참조) | AI 행동 규칙 |
| `vision/goals.md` | **부분** — 배정된 것만 | 전부 내리면 child 가 남의 목표를 진다 |
| `vision/memory/` | **전파 안 함** | cell 별 맥락. 섞이면 양쪽 오염 |
| `environment/` | **전파 안 함** | descriptive. repo 마다 사실이 다르다 |

**형태**: 복사 동기화 (`genome/inherited/`, 읽기 전용). 참조 방식은 상위 접근 불가 시 하위가 절름발이가 되어 원칙 3 을 깬다.

**갱신 시점** — 전신 문서의 미결 3번은 **닫혔다**: 시각이 아니라 **SHA 비교**다. 상속본이 어느 SHA 의 사본인지 기록하고, 상위 선언의 현재 SHA 와 다르면 낡은 것이다. 머신 시계에 의존하지 않는다.

**상속분은 하위가 수정할 수 없다.** 이의는 backlog(`type: genome-change`)로 제기하고 **상위의 adapt phase 가 판단**한다.

## 6. 통신 `[위치·채널 확정 / 항목 형식은 §4 에 종속]`

### 6.1 가능한 채널 `[확정]`

원칙 2(남의 `.reap/` 에 쓰지 않는다)를 지키면 논리적으로 셋이다:

| 채널 | 형태 |
|---|---|
| **publish** | 자기 repo 에 쓴다 — 인터페이스 선언, 버전, deprecation |
| **read** | 남의 선언을 **특정 SHA 로** 읽는다 (핀 고정) |
| **out-of-band** | PR, 이슈, 사람. REAP 밖 |

### 6.2 알림 채널 — 능동적 통지 `[잠정 · 재검토 중]`

6.1 만으로는 **모든 전파가 수신자의 탐색에 의존**한다. 최소한 *"전파할 것이 발생했다는 사실"* 은 발신자가 확언적으로 알릴 수 있어야 한다.

**설계 제약 셋** (이걸 못 박지 않으면 registry 로 미끄러진다):

| | 규칙 |
|---|---|
| **내용** | 채널은 **내용을 나르지 않는다.** `(종류, 대상, SHA)` — 존재 주장 + 주소뿐 |
| **강제** | 강제는 채널의 성질이 아니라 **게이트의 성질**이다. 채널은 그대로 pull |
| **커서** | **소스별** 커서. 전역 위치는 금지 |

**내용을 나르면 안 되는 이유**: 실으면 채널이 SSOT 가 되고 발신 cell 의 repo 와 불일치할 수 있다. `(breaking, api-X, abc123)` 만 실으면 **모든 항목이 반증 가능**하다 — 가서 `abc123` 을 읽었는데 그런 변경이 없으면 항목이 틀린 것이다. **채널은 틀릴 수는 있어도 권위가 될 수 없다.**

**강제가 게이트에 있어야 하는 이유**: A가 B를 강제할 수단은 원래 없다. 그러나 **B가 `consumes api-X` 를 선언했다면 B의 게이트가 B를 막을 수 있다** — 커서가 밀려 있으면 `reap run start` 가 거부한다. 원칙 6 이 유지되고, 아무것도 소비하지 않는 cell 은 영원히 막히지 않는다.

**커서가 소스별이어야 하는 이유** (증명):

> 전역 커서 하나는 **전역 순서**를 요구하고, 전역 순서는 **순번을 매기는 자**를 요구한다. 그게 조정자다.
> 소스별이면 불필요하고, 필요하지도 않다 — **인터페이스의 제공자는 1개이므로 어떤 대상에 대한 주장은 전부 한 소스에서 나온다.** 한 소스 안의 순서는 append 순서로 이미 전순서이고, 서로 다른 소스의 항목은 같은 대상을 말하지 않는다.

형식: `cursor: { <cell-id>: <마지막 소비 항목 SHA> }`. **시각이 아니라 SHA.**

### 6.3 입장 규칙 — 이 설계의 생사 `[잠정]`

비용은 **모든 cell 이 모든 generation 시작마다** 낸다. 채널 크기는 **활동량이 아니라 파손 횟수에 비례**해야 한다.

**판정 한 줄**: *"이 항목을 읽고 어떤 cell 도 아무 결정을 하지 않아도 되는가?"* → Yes 면 넣지 않는다.

| 허용 | 금지 |
|---|---|
| 인터페이스 공개 / 버전 추가 | generation 완료 — lineage 에서 당겨라 |
| **breaking change · deprecation** (은퇴 지점 포함) | 테스트 수치, 진행 상황 |
| 인터페이스 은퇴 | 알림성 소식 전반 |
| `governs`: 상위 genome/invariants 이동 | |
| cell 이전 / 폐기 (remote 변경) | |

### 6.4 확인 시점 `[잠정]`

| 시점 | 무엇 |
|---|---|
| SessionStart | **네트워크 없음.** 로컬 캐시 + 얼마나 낡았는지만 보고 |
| generation start · validation | **여기서만 fetch.** 답이 행동을 바꾸는 두 지점 |

`load-context` 는 빨라야 하므로 매 세션 네트워크는 금지다.

### 6.5 도달 불가는 "소식 없음"이 아니다 `[확정]`

막으면 네트워크 장애가 전 조직의 작업을 멈춘다. 조용히 통과하면 *"부재 단언은 스스로 먼저 증명한다"* 를 위반한다.

`check-version-floors.sh` 의 3분기를 쓴다: **진행하되 artifact 에 "확인 못 함 + 마지막 확인 SHA" 를 명시 기록.** amber.

### 6.6 커서를 미는 것 ≠ 대응하는 것 `[잠정]`

읽고 "나와 무관"이라 판단하는 건 정당하지만 무기명 통과가 되면 커서는 고무도장이 된다.

**breaking 항목을 지나칠 때 처분을 기록**한다: `acted` / `not-applicable` / `deferred`(→ backlog 자동 생성).
선례: **`EvaluatorConcern`** 이 같은 모양이다 — append-only 상태 채널 + 뒤 phase 가 반드시 읽음.

### 6.7 채널의 위치 `[확정 — §0 전제로 닫힘]`

**발신 cell 의 repo 안. 공유 미러 repo 는 두지 않는다.**

| | 발신 cell repo 안 | 공유 미러 repo |
|---|---|---|
| 쓰기 권한 | **자기 것뿐 — 새 결합 0** | 공통 write 필요 |
| 읽을 곳 | 선언된 provider N곳 | 1곳 |
| 엣지 없는 cell 의 소식 | 도달 불가 | 도달 가능 |

미러의 유일한 우위는 마지막 줄인데, **단일 머신 전제에서 N곳을 읽는 비용이 사실상 0** 이므로 그 우위가 값을 하지 못한다. 새 결합(공통 write 권한·경합·가용성)만 남는다.

조직 차원 브로드캐스트가 필요해지면 **발신 cell 이 하나 더 생기는 것**으로 표현한다 — 모두가 그 cell 을 consume 선언한다. 새 메커니즘이 아니라 기존 모델의 사용법이다.

### 6.8 부수 효과 — master node 가 불필요해진다 `[잠정]`

master node 가 값을 하는 유일한 질문은 **"지금도 나를 쓰는 소비자가 있는가"**(은퇴 판단)였다. 채널이 이걸 다르게 푼다:

> A는 소비자 목록을 알 필요가 없다. 알아야 할 것은 **소비를 선언한 모든 cell 이 강제로 보게 되었다**는 사실뿐이다.

deprecation 을 발행하고 은퇴 지점을 명시하면 선언한 소비자는 자기 게이트 때문에 반드시 본다. **in-edge 목록 없이 성립한다.**

→ master node 는 "한 질문에 필요"에서 **"선택적 편의"로 강등**.

구멍(정직하게): 선언하지 않고 쓰는 cell 에는 도달하지 않는다. 다만 미선언 의존은 어느 시스템에서도 안 보이며 원칙 6 과 일관된다.

## 7. 무결성 — 예방과 부인방지는 다른 것이다 `[확정]`

### 7.1 왜 nonce 를 경계 밖으로 옮길 수 없나

**cell 내부 nonce 가 작동하는 이유**: 쓰는 프로세스가 하나(로컬 CLI), 상태가 공유(`current.yml`), 막는 대상이 **적대자가 아니라 성급한 agent**. `invariants.md` 의 *"Do not forge nonce tokens"* 가 지시문인 것이 증거다 — 암호 보안이 아니라 **절차적 인터록**이다.

경계를 넘으면 셋 다 사라진다. 그리고 결정적으로 **B의 repo 는 B의 것이라 B를 막을 방법이 원래 없다.** 전신 문서 §8 이 이미 인정했다: *"사람이 child repo 에서 parent 몰래 세대를 도는 것은 정상 경로다."*

### 7.2 그래서 층을 나눈다

> **B가 약속을 깨는 것은 막을 수 없다. B가 "안 깼다"고 주장하는 것과, A가 B의 약속을 조용히 잘못 아는 것은 막을 수 있다.**

자물쇠가 아니라 **원장(ledger)** 이고, **git 이 이미 그 원장이다** — 내용 주소 해시의 Merkle DAG, 위조 불가, 삭제하면 티남, 서명 태그까지 무료.

| | 어디서 | 무엇을 | 수단 |
|---|---|---|---|
| 관측 | 경계 너머 | 상대가 무엇을 약속하나 | SHA 고정 읽기 |
| **부인방지** | 경계 **위** | 누가 언제 무엇을 약속했나 | git 커밋 / 서명 태그 |
| **강제** | 경계 **안** | 낡은 계약 위에서 진행 금지 | **기존 nonce·stage gate 재사용** |

**새 cross-cell nonce 프로토콜은 필요 없다. 기존 게이트가 경계 밖 사실을 입력으로 받으면 된다.**

### 7.3 악수는 두 개의 독립 선언이다

A가 B의 `api-X@2` 를 SHA `abc123` 에서 소비한다면 **A는 자기 repo 에만 쓴다**:

```yaml
consumes:
  - interface: api-X
    version: 2
    provider: <remote>
    pinnedAt: abc123     # 제공자 선언 커밋
```

B도 자기 repo 에만 쓴다. **둘 다 상대에게 쓰지 않는데 같은 content hash 를 가리키므로 대조가 성립한다.**
선례: lockfile 의 integrity hash, in-toto / SLSA attestation.

### 7.4 `governs` 도 경계를 넘어 강제되지 않는다

하위의 상속 genome 이 상위 SHA 의 사본이면 **하위의 CLI 가** 진행을 거부할 수 있다 — 사본이 로컬 수정됐거나(해시 불일치), 상위 선언 SHA 가 사라졌을 때. 상위가 손을 뻗는 게 아니라 **하위가 상위를 선언함으로써 스스로를 구속한 것**이다.

### 7.5 동시성 — §0 전제가 만든 문제 `[미결 · 최우선]`

**단일 머신 + 공유 가변 상태 + 다중 agent** 는 REAP 이 아직 답을 갖지 않은 조합이다. §0 에 적은 실제 발생 사례가 증거다.

**깨지는 지점** (관측된 것과 구조적으로 예상되는 것):

| 대상 | 증상 |
|---|---|
| `life/current.yml` | 단일 슬롯인데 **잠금이 없다.** 두 agent 가 각자 자기가 소유자라고 믿는다 |
| 로드된 context | 세션 시작 시 읽고 **다시 확인하지 않는다.** 세계관이 조용히 낡는다 |
| `life/backlog/` | 동시 생성·소비. `consumed` 마킹 경합 |
| git index | **저장소당 하나.** 경로 없는 `git commit` 이 남의 staged 변경을 함께 담는다 |

**설계 재료 — 이미 갖고 있는 것**:

- **nonce 는 이미 CAS(compare-and-swap) 다.** `pendingTransitions` 는 특정 상태에 대해 발행되고, 상태가 움직이면 검증에 실패한다. **빠진 것은 쓰기가 아니라 읽기다** — context 로드가 이 검증에 참여하지 않는다
- **cell 이 동시성 단위의 자연스러운 후보다.** cell 하나 = 활성 generation 하나 = **활성 agent 하나**. cell 간 병렬은 공유 가변 상태가 없으므로 공짜다. 위 사고는 **두 agent 가 같은 cell 에** 있어서 났다 — 모델이 이미 금지하는 상태이나 강제되지 않았다

**따져야 할 축**:

1. **lease vs. detect** — 잠금을 잡을 것인가(죽은 agent 의 stale lock 을 누가 거두나 — daemon 을 두지 않기로 했다), 아니면 낙관적으로 진행하고 어긋남을 감지할 것인가(nonce 확장)
2. **읽기의 재검증 시점** — 매 도구 호출? stage 전환? 그 사이 비용
3. **worktree** — 한 cell 을 두 worktree 로 열면 `.reap/` 사본이 둘이다. 그건 merge 문제의 재림이다. **`.reap/` 상태는 worktree 별이 아니라 cell 별이어야 하는가**
4. **git index 공유** — 경로 지정 커밋을 규약으로 삼을 것인가, 아니면 cell 단위 격리로 구조적으로 막을 것인가

## 8. 원칙

1. `[확정]` **SSOT 는 cell 에 있다.** 전역에 준하는 것은 전부 파생물이며, **재생성 불가능해지면 설계 실패**다 — 지우고 다시 만들어 같지 않으면 이미 SSOT 가 된 것이다
2. `[확정]` **전파는 1-hop.** impact 는 전역 순회가 아니라 지역 판정의 사슬 — 싸서가 아니라 **정확해서**
3. `[확정]` **순환은 오류가 아니라 사실.** 보고하되 금지하지 않는다 (`governs` 만 예외 — 조상 걸음으로 로컬 판정)
4. `[확정]` **master node 는 관례이지 인프라가 아니다.** opt-in, 부재 시 정상 동작 (§6.8 로 강등됨)
5. `[확정]` **낡음은 SHA 로 로컬에서 답한다.** 시각·머신 상태에 의존하지 않는다
6. `[잠정]` **강제는 자기 선언에서 나온다.** cell 은 자기가 선언한 것에 의해서만 구속된다. 아무것도 선언하지 않은 cell 은 아무 제약 없이 정상 동작한다
7. `[미결]` **알림은 존재만 나르고, 소비는 자기 게이트가 강제하며, 커서는 소스별 SHA 다.** ← §6.2, 재검토 중

**전신 문서에서 승계한 원칙** (여전히 유효):

- **cell 단독 실행이 항상 가능해야 한다.** 혼자 clone 해서 `/reap.evolve` 를 돌리면 그냥 동작한다
- **opt-in.** cell 을 모르는 기존 프로젝트의 동작은 byte-identical (`evaluator` 패턴)
- **남의 `.reap/` 에 쓰지 않는다**

## 9. 도달률은 절대수로 노출한다 `[확정]`

`reap index` 의 교훈이 여기서 훨씬 위험하다 — *"`impact` 를 믿기 전에 import 해석률을 읽어라. 낮으면 빈 blast radius 는 없음이 아니라 모름이다."*

§0 전제에서 네트워크발 미도달은 사라지지만 **미해석 자체는 사라지지 않는다** — 오타난 인터페이스 ID, 삭제·개명된 cell, 파싱 실패. 그 결과가 조용한 0 이다.

- **절대수로 보고한다** — `38/41 cell 해석, 3 미도달`. 비율만 두면 `0/0` 이 100%로 통과한다
- **cell 별로 마지막에 읽은 선언의 SHA 를 기록**한다. "낡았는가"가 전역이 아니라 **cell 단위로** 답해진다

## 10. 채택하지 않을 것 — 각각의 기각 사유

| 기각 대상 | 사유 |
|---|---|
| **블록체인을 메시징 기반으로** | git 이 이미 원장이다(§7.2) — 내용 주소 무결성·변조 감지·서명·한 작성자 내 순서. 차집합은 ①특권적 호스트의 부재 ②작성자 간 전역 전순서 ③단일 호스트 독립 가용성 셋뿐인데, **②는 §6.2 에서 "필요 없다"를 증명했고**(소스별 커서로 충분하며, 전역 순서를 요구하면 기각한 조정자가 돌아온다), ①③은 **조직 경계 문제**라 §0 의 단일 조직 전제에서 발생하지 않는다. **대표 성질이 우리가 의도적으로 원하지 않는 것**이다 |
| **다중 머신 지원** | §0 범위 밖. 개발 환경의 분산은 사람의 신체 제약 때문이었고, 그 근거가 agentic 환경에서 사라진다. (운영 환경의 분산은 부하·가용성 때문이며 별개 문제다) |
| **전역 registry 를 SSOT 로** | drift 가능 + cell 단독 동작을 깬다. Backstage 도 카탈로그를 SSOT 가 아니라 캐시로 둔다 |
| **discovery 서버 (Eureka 류)** | 정당화 근거는 **인스턴스 churn 이 정적 설정을 앞지른다**는 것. cell 은 저장소이고 주소가 몇 년 안 바뀐다. **근거가 되는 성질이 없다** |
| **global transaction (2PC/saga)** | N개를 하나의 원자적 결과에 합의시키는 장치. REAP 에는 "전부 커밋 아니면 전부 롤백"이 없고 **이미 반대로 결정했다**(fail-fast 미채택, barrier 미강제). 들이면 barrier 가 되돌아온다 |
| **전역 순환 탐지를 위한 fold** | `governs` 는 조상 걸음으로 로컬 판정, `depends-on` 순환은 오류가 아님 (§3.2). **초안에서 필요하다고 적었다가 철회했다** |
| **`relates-to` 엣지** | 아무것도 흐르지 않는 엣지는 아무것도 뜻하지 않는다 |
| **M3 내포형 실행** (상위가 하위 lifecycle 을 동기 실행) | context 폭발 + 실패 전파 + self-fitness 위험 |
| **merge 확장으로 구현** | merge 는 "결국 하나가 된다"를 전제 (§2.3) |
| **fail-fast** | 독립성과 양립 불가 |
| **상위가 하위 파일에 직접 쓰기** | 한 번 허용하면 소유권 경계가 사라진다 |
| **CI 오케스트레이터화** | REAP 은 빌드 파이프라인이 아니다 |

### 11-4. fitness 이중 부담
`governs` 축에서 상위가 하위를 평가하면 self-fitness 인가.
**잠정 결론**: 하위의 fitness 는 하위에서 인간이 한다. 상위는 평가하지 않고 **수확(harvest)** — 배정한 것과 돌아온 것을 **대조**할 뿐이다. 대조는 사실 확인이지 적합도 판정이 아니다.
**남은 문제**: 사람이 한 명이면 두 번 판정한다. 승계 경로가 필요할 수 있으나, 승계가 "상위가 평가한 것으로 간주"가 되면 결론이 무너진다.

### 11-5. Milestone 과의 접점
상위의 milestone 이 하위들에 분배되는가. 별도 축.

## 12. 로드맵

**제약이 없는 것부터 만든다.** 전신 문서는 Phase 1 을 `governs` 관측으로 잡았는데, 그건 셋 중 **제약이 가장 강하고 되돌리기가 가장 비싼** 엣지다.

| | 내용 | 전역 fold 필요? | 완료 조건 |
|---|---|---|---|
| **P0** | 이 문서의 미결 닫기 (§11-1, §11-2 우선) | — | 미결에 답이 적히고 기각에 사유가 적혔다 |
| **P1** | 인터페이스 선언 + `provides`/`consumes`. 순수 카탈로그. **전파 0** | **불필요** | cell 이 자기 막을 선언하고, 다른 cell 이 그것을 SHA 로 핀한다. cell 을 모르는 프로젝트는 byte-identical |
| **P2** | `depends-on` 파생, impact, 알림 채널 + 커서 게이트 | §6.7 에 종속 | 제공자가 breaking 을 발행하면 소비자 게이트가 커서를 요구하고, 처분 기록 없이는 진행하지 못한다 |
| **P3** | `governs` — 상속 + 상향 요약 + 충돌 감지 | 조상 걸음만 | 상위 genome 변경이 하위에 도달하고, 하위가 상속분을 수정하면 막힌다 |
| **P4** | goal 배정 + 수확 대조 | — | 배정↔결과 대조 기록이 남는다 |

**세대 배분**: 최소 4~5. P1 단독 1세대, P2 는 채널 설계 때문에 2세대가 될 수 있다.

## 13. 검증 전략

cell 은 **두 프로젝트가 있어야 검증된다** — 단위 테스트로 잡히지 않는다.

- **scenario test**: `tests/fixtures/` 에 cell 두 개를 만들고, 한쪽이 인터페이스를 바꾼 뒤 다른 쪽 게이트가 실제로 막히는지 확인
- **회귀 보장**: cell 미설정 프로젝트의 모든 출력이 byte-identical (`evaluator` opt-in 검증 패턴 재사용)
- **검사를 먼저 실패시킨다** — 구현 전에 돌려 fail 을 확인한다
- **머신 상태를 읽지 않는다** — `git init -b main` + repo 별 identity. 경로 비교는 realpath 정규화
- **§9 도달률**: 절대수 단언. `0/0` 이 통과하지 않는 것을 negative test 로 확인
- **원칙 1 재생성 검사**: 미러/파생물을 지우고 다시 만들어 **동일한지** 단언. 다르면 SSOT 가 된 것이다
