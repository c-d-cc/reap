# 층2 게이트가 권한 거부를 슬래시 커맨드 미노출로 오진한다 — 가짜 음성

## Problem

0.17.6 릴리즈 직전 `scripts/check-agent-integration.sh` 를 돌렸더니 **FAIL 이 났고, 그 진단이 틀렸다.**

```
ok    project initialised at a temporary path
ok    agent completed (subtype: success, cost: $0.2582815)
FAIL  no generation was created
      ".reap/life/current.yml is absent, so /reap.start never ran.
       The files are in place — the client did not surface them as a
       slash command. This is the gen-063 failure exactly."
```

**agent 가 한 말은 정반대였다:**

> `/reap.start` 슬래시 커맨드는 **정상적으로 로드되었지만**, 그 안에서 지시하는 첫 단계인
> `reap run start` 실행이 **auto mode 권한 분류기에 의해 차단**되었습니다.
> `Permission for this action was denied by the Claude Code auto mode classifier.`
> 우회 실행은 지시하신 대로 시도하지 않았습니다.

권한만 열고 같은 절차를 손으로 재현하니 **통과했다** (스크립트 미수정, 임시 프로젝트에만 설정):

```
.claude/settings.local.json  →  { "permissions": { "allow": ["Bash(reap:*)"] } }
claude -p ... --allowedTools "Bash(reap:*)" --output-format json

permission_denials  []            ← 거부 0건
subtype             success       num_turns 5   cost $0.2760
current.yml         id: gen-001-1be3ff
                    goal: agent integration probe      ← 정확히 일치
                    type: embryo / stage: learning / phase: entry
```

즉 **슬래시 커맨드·`@` import·SessionStart hook·CLI 는 전부 정상**이었고, 실패 원인은 오직 권한이었다.

### 왜 이것이 결함인가

스크립트 주석은 이렇게 적고 있다:

> "슬래시 커맨드가 인식되지 않았다면 `current.yml` 은 그냥 존재하지 않을 것이다."

**이 명제는 한 방향으로만 참이다.** 역은 성립하지 않는다 — `current.yml` 부재는 커맨드 미노출로도,
**권한 거부**로도, CLI 크래시로도, `reap init` 실패로도 생긴다. 스크립트는 `SLASH_COMMAND_UNAVAILABLE`
토큰 하나로 구분을 시도하지만, 그 토큰은 *"커맨드가 없는 경우"* 만 덮고
**"커맨드는 있는데 진행이 막힌 경우"** 는 커버 범위 밖이다.

longterm 이 이미 명문화한 실패 형태다 — *"부재를 주장하는 assertion 은 스스로 먼저 증명한다.
크래시·비정상 출력·필드명 변경도 부재로 읽힌다."* 여기에 **권한 거부**가 하나 더 추가된 것이다.

### 방향이 나쁘다 — 가짜 음성이다

없는 결함을 있다고 보고한다. 게다가 **개발자 환경이 auto mode 면 항상 재현된다** —
즉 `$0.25` 짜리 유료 검사가 매번 존재하지 않는 통합 결함을 가리킨다.

실제로 이번 릴리즈에서 **$0.534 가 들었다** (1차 $0.258 은 이 결함 때문에 버려졌고,
2차 $0.276 이 진짜 답을 줬다). 이 상태로 두면 다음 릴리즈에도 같은 값을 낸다.

그리고 더 나쁜 두 가지:
- 릴리즈 직전에 FAIL 을 보면 **존재하지 않는 문제를 쫓게 된다**
- 몇 번 반복되면 사람이 그 FAIL 을 **무시하기 시작한다** — 그러면 진짜 gen-063 이 와도 안 보인다.
  genome 이 *"항상 무언가를 보고하는 검사는 사람이 스크롤로 넘긴다"* 로 이미 적어둔 그 경로다

## Solution

두 가지를 **함께** 한다. 하나만으로는 부족하다.

**S1. 원인 자체를 없앤다 — 임시 프로젝트에 권한을 심는다**

`reap init` 직후 임시 프로젝트에 설정 파일을 쓴다:

```json
{ "permissions": { "allow": ["Bash(reap:*)"], "deny": [] } }
```

**임시 디렉토리 안에만 쓴다** — 스크립트가 이미 지키는 성질(현재 설치를 읽기만 하고
쓰기는 임시 프로젝트에만)을 유지한다. 사용자의 `~/.claude/` 는 건드리지 않는다.

`claude -p` 호출에도 `--allowedTools "Bash(reap:*)"` 를 붙일지는 구현 시 판단
(둘 다 넣어도 무해하며, 이번 수동 재현은 둘 다 넣고 통과했다).

**S2. 판정이 원인을 구분하게 한다 — S1 이 있어도 필요하다**

S1 은 *알려진* 한 원인만 없앤다. 다음 원인은 또 다른 얼굴로 온다(CLI 크래시, init 실패,
네트워크). 그러므로 **부재를 하나의 원인으로 단정하는 문장 자체를 고친다**:

- `permission_denials` 가 비어 있지 않으면 → "권한 때문에 검사가 아무것도 측정하지 못했다"로
  보고하고 **FAIL 이 아니라 SKIP/amber** 로 낸다. *검사 실패*와 *측정 실패*는 다르다
- `subtype`, `is_error` 를 먼저 읽어 **agent 실행 자체가 성공했는지 선단언**한 뒤에야
  `current.yml` 부재를 해석한다
- FAIL 문구에서 *"This is the gen-063 failure exactly"* 라는 **단정을 제거**한다.
  가능한 원인을 열거하고 agent 의 보고를 함께 싣는다

## 검증

**이 검사를 고치는 작업이므로, 고친 검사가 두 상태를 실제로 구분하는지 보여야 한다.**

- [ ] `[negative]` 권한을 막은 상태로 실행 → **FAIL 이 아니라 SKIP/amber**, 문구가 권한을 지목
- [ ] `[negative]` 권한을 연 상태로 실행 → **통과**, `current.yml` 생성 (이번에 실측한 그 조건)
- [ ] `[negative]` 슬래시 커맨드를 실제로 지운 상태로 실행 → **FAIL**, gen-063 경로가 여전히 잡힌다
      ← **이것이 가장 중요하다.** S1 이 권한 경로를 없애면서 진짜 결함까지 못 잡게 되지 않았는지가
      이 수정의 유일한 위험이다
- [ ] 세 경우의 **비용을 기록**한다. 유료 검사이므로 몇 번 돌렸는지가 정보다

주의: 위 negative 는 각각 `~$0.25` 다. 셋을 다 돌리면 약 $0.75~1.0. **그만한 값이 있다** —
이 검사는 릴리즈마다 돌고, 지금 상태로는 매번 틀린 답을 준다.
