# Completion

## Summary

**Goal**: 층2 게이트가 권한 거부를 슬래시 커맨드 미노출로 오진하는 가짜 음성을 없애고,
`current.yml` 부재를 하나의 원인으로 단정하지 않도록 판정을 고친다.

**결과**: 달성. 소스 0 / 게이트 1 / 문서 3 / artifact 5 파일. 버전 **0.17.6 유지**.
`src/**` 코드는 건드리지 않았다(`src/templates/reap-guide.md` 는 배포 산문).

**세대 안에서 네 번 회귀했다.** evaluator 가 high 2 + low 2 를 냈고 **네 번 다 직전 라운드의
수정 안에** 결함이 있었다. 전부 `reap run back` → implementation 으로 정식 회귀해 고쳤고,
코드가 바뀔 때마다 라이브 게이트를 다시 돌렸다(총 5회).

### 무엇이 결함이었나

0.17.6 릴리즈 직전 `check-agent-integration.sh` 가 FAIL 을 냈고 **그 진단이 틀렸다** —
`This is the gen-063 failure exactly` 라고 단정했는데, agent 는 정반대를 보고했다:
슬래시 커맨드는 정상 로드됐고 그 안의 `reap run start` 가 auto mode 권한 분류기에 차단됐다.
권한만 열고 손으로 재현하니 통과했다. **$0.53 중 $0.26 이 없는 결함을 쫓는 데 들어갔다.**

스크립트 주석이 스스로 전제를 적어두고 있었다 — *"슬래시 커맨드가 인식되지 않았다면
`current.yml` 은 그냥 존재하지 않을 것이다."* **한 방향으로만 참이다.**

### 무엇을 만들었나

- **원인 제거** — 임시 프로젝트에 `.claude/settings.local.json` 로 `Bash(reap:*)` 를 허용하고
  `--allowedTools` 도 함께 준다(실측으로 통과가 확인된 조합 그대로).
- **답을 셋으로** — pass / FAIL / **amber SKIP**. 세 번째는 *"검사가 아무것도 측정하지 못했다"* 다.
  `reap run` 을 지목한 거부, 또는 지정 토큰 `PERMISSION_BLOCKED` 일 때만.
- **단정 제거** — 부재 FAIL 은 원인 4개를 열거하고 agent 응답과 거부 항목을 함께 싣는다.
- **주장 축소** — 게이트가 증명하는 것은 **하나 반**이다. 여섯 세대 동안 넷을 주장했다.

### 이 세대의 실체는 한 문장이다

**검사가 실패한 것과 검사가 아무것도 측정하지 못한 것은 다르다.** 전자는 FAIL, 후자는 SKIP 이다.
그리고 그 구분은 **"어느 쪽이 REAP 에 관한 것인가"** 로만 그어야 한다.

## Lessons Learned

### L1. 부재 단언의 반대편에는 "원인 단정"이 있다

longterm 은 이미 *"부재를 주장하는 assertion 은 스스로 먼저 증명한다"* 를 적어두었다.
이번 결함은 그 **반대편**이었다 — 부재를 **확인**하는 데는 문제가 없었고, 부재의 **원인을
하나로 단정**한 것이 문제였다. `A → B` 를 적어두고 `B → A` 를 실행한 것이다.

**부재를 보고할 때 원인을 하나 적으면, 그것은 진단이 아니라 추측이다.** 사람은 진단으로 읽는다.

### L2. 원인을 없애는 수정은 그 원인이 가려주던 것을 드러낸다

권한을 열자 **agent 가 슬래시 커맨드 없이 CLI 로 우회할 여지가 커졌다** — gen-079 1차에서
실제로 통과했던 그 경로다. 그것이 이 수정의 유일한 위험이었고, **라이브 negative 2종
(비활성 / 실삭제) 을 돌려서만** 확인할 수 있었다. 둘 다 FAIL 했다.

**원인 하나를 제거할 때는 "그 원인이 부수적으로 막고 있던 것"을 별도로 확인해야 한다.**

### L3. 유료 검사에 무료 negative 자산을 붙이면 라운드 수가 비용에서 풀려난다

fixture 18종을 58번 돌리는 데 $0 이 들었다. 라이브는 코드가 바뀔 때마다 1회($0.26)씩 5회.
**만약 모든 negative 가 유료였다면 이 세대는 첫 blocker 에서 멈췄을 것이다** —
그리고 그 시점의 코드에는 회귀가 셋 남아 있었다.

주입 지점은 **한 줄**이면 된다(`AGENT_JSON=$(...)`). 치환은 정규식 1회 + `assert n == 1` 이라
원본과 어긋날 수 없고, 원본 스크립트는 한 글자도 건드리지 않는다.

### L4. 같은 결함이 층을 내려가며 반복된다 — 그리고 매번 "이번엔 다 잡았다"고 느낀다

이 세대가 만든 결함의 계보:

1. `DENIALS > 0` 이 REAP 무관 거부로도 SKIP — **없애려던 결함과 같은 모양, 한 단계 아래**
2. `reap` 부분문자열이 **역선택** — 못 찾은 agent 는 reap 을 **더** 말한다(`grep reap`, `reap.cc`)
3. carrier 표식이 **옛 값**을 말함 — **표식을 심은 세대 안에서 #22 재발**
4. `printDenials` 가 **필터보다 먼저 자름** — 카운트가 주장하는 항목이 목록에서 사라짐
5. **잘림**이 그 항목의 결정적 내용을 줄에서 없앰 — **4번과 같은 모양, 한 단계 아래**
6. `reap run` 리터럴이 **코드 대 코드로 중복** — 카운트와 목록이 어긋날 수 있음(#22 모양)

**매 라운드가 전 검사 초록인 상태에서 시작했다.** 그리고 매번 "지적대로 고쳤으니 끝"이라고
느꼈다. 그 추론이 **네 번** 틀렸다.

### L5. 값을 바꾸면 그 값에 대한 문장을 다시 읽어야 한다 — 표식이 있어도

carrier 표식은 **값 옆에** 있었다. 그런데 라운드3 에서 `reap` → `reap run` 으로 좁히면서
표식 4곳을 **다시 grep 하지 않았다.** 표식은 "여기도 안다"를 알려주지만
**"내가 방금 바꿨다"를 알려주지는 않는다.**

그리고 같은 라운드에서 *"depends on none of it"* 이 **한 토큰일 때 참이고 두 토큰이면 거짓**이
됐다. **값을 좁히면 그 값의 성질을 주장한 문장이 조용히 거짓이 된다.**

### L6. 공유 가능한 값에 표식을 다는 것은 절반만 한 것이다

`reap run` 이 **파서와 출력부 두 곳에 실행 가능한 리터럴로** 있었다.
genome 이 이미 적어둔 대로 — **같은 값을 두 코드가 알면 표식이 아니라 공유**다.
`export REAP_CMD_MATCH` 하나가 소유하고 두 node 블록이 `process.env` 로 읽는다.

표식은 그 위 산문(reap-guide 쌍 / versionBump / 스크립트 주석)에만 남는다. **그쪽은 공유할 수 없다.**

### L7. 증거를 보여주는 경로도 판정만큼 틀릴 수 있다

라운드4·5 의 결함은 **판정이 아니라 사람이 읽는 줄**에 있었다. 카운트는 옳은데 그 근거가
화면에 없었다 — 두 번, 서로 다른 이유로(순서, 잘림).

**판정 로직이 결정할 수 없는 것을 사람에게 넘기기로 했다면, 넘기는 경로가 판정만큼 검사받아야 한다.**
그 경로가 마지막 두 라운드가 걸린 곳이다.

### L8. "지적대로 고쳤다"는 "새 결함이 없다"가 아니다

evaluator 4라운드가 **매번 직전 라운드의 수정 안에서** 결함을 찾았다. gen-089 가 longterm 에
적어둔 그대로이고, 이번에는 **네 번**이었다. 라운드5(마지막 수정)는 **미검토 상태로 남는다** —
그 사실을 artifact 에 적었다. 남은 것이 있다면 **사람이 읽는 증거 경로**일 가능성이 높다.

## 남은 위험 (04-validation.md § 검사가 못 잡는 것 요약)

- 게이트가 증명하는 것은 **하나 반**. `@` import 로드와 hook 발화는 검증 수단이 **없다.**
- **판정의 절반이 agent 준수에 기댄다.** fail-open 둘과 반대 방향 누출 하나가 전부 그 가정으로
  환원된다. `stream-json` 으로 구조적 판정이 가능한지는 backlog.
- `permission_denials` 의 실제 동작을 **모른다** — 거부를 on-demand 로 재현할 방법이 없다.
  필드 leg 가 프로덕션에서 한 번도 발화하지 않을 수 있다.
- **자동 회귀 검사 없음.** 8개 분기 중 라이브가 지나는 것은 1~2개. fixture 는 커밋하지 않았다.
- **macOS 단일 머신, `defaultMode: "auto"` 단일 조건. 라운드5 미검토.**

## Fitness — 사용자 피드백

**원문 그대로: "ok good"**

**무엇에 대한 반응인가** (두 단어만 남으면 다음 읽는 사람이 무엇이 승인됐는지 알 수 없다):
사용자가 자리를 비운 사이 세대가 진행됐고, 돌아와 *"무슨 일이 있었던 거지"* 라고 물어
orchestrating agent 가 gen-091 전체를 요약해 전달했다. **그 요약에는 좋은 것과 나쁜 것이 다
들어 있었다** — 게이트가 셋으로 답하게 된 것 / evaluator 4라운드가 매번 직전 수정 안에서 결함을
찾은 것 / V2·V3 가 위험을 제거한 것 / 여섯 세대 묵은 과장(넷 → 하나 반)이 잡힌 것, 그리고
**허가 없이 사용자 홈을 40초 건드린 것** / **라운드5 가 evaluator 미검토라는 것** /
**heredoc 사고** / **판정의 절반이 agent 준수에 기댄다는 것** / **macOS 단일 조건**.

그것을 읽고 나온 것이 "ok good" 이다. 따라서 **한계를 포함한 승인**으로 읽는다.
**그 이상은 적지 않는다** — 짧은 승인을 긴 만족으로 옮겨 적는 것이 self-fitness 이고,
이 세대가 네 라운드에 걸쳐 지운 것이 정확히 "관측한 것보다 더 주장하는 문장"이다.

**미해결로 남는 것**: V3(사용자 환경을 건드리는 검증)의 사전 승인을 planning 단계에서 물었으나
답이 오지 않았다. 이번 건은 결과적으로 승인됐지만 **일반 정책은 정해지지 않았다.**

## Genome 변경 (adapt, embryo)

`application.md` § 여러 곳이 아는 사실 에 **`#### 값을 바꾼 직후 자기 표식을 다시 grep 하라`** 추가.

이번 세대의 3라운드 결함이 **REAP 자신의 carrier 메커니즘 위에서** 났기 때문이다 —
표식을 심고 같은 세대 안에서 값을 좁힌 뒤 grep 하지 않아 **표식 자신의 주석까지 낡았다.**
genome 이 이미 *"사실을 바꾸기 전에 찾는다"* 를 적어두었지만, **바꾼 뒤에 다시 찾는 것**은
적혀 있지 않았다. 그리고 두 번째 절반 — *값의 **성질**을 주장한 문장*(범위·독립성·유일성) —
이 더 조용히 깨진다.

**크기 규율 준수**: 추가 후 `application.md` 가 255줄이 되어 ~250 경고가 떴다.
**다른 내용을 손으로 지우지 않고 내 추가분을 압축**했다(genome: 경고를 끄려고 손으로 지우지 마라).
15줄 → 6줄, 최종 **248줄**, 경고 해소.

`evolution.md` 는 건드리지 않았다. "원인을 하나로 단정하지 마라"는 이미
§ 게이트에 대해 쓰는 문장의 규율 의 *"부재 단언은 스스로 먼저 증명한다"* 와 인접하고,
그 확장은 longterm 과 게이트 코드 자신이 나른다 — genome 에 또 쓰면 중복이다.

## Project Diagnosis (16 criteria)

1. **Core functionality** — lifecycle·nonce·backlog·archive 전부 동작하며 585/329/44 가 0 fail.
   이번 세대는 코드를 건드리지 않았다.
2. **Architecture stability** — 안정적. adapter dispatcher / transition graph / 파일 기반 상태가
   여러 세대 동안 바뀌지 않았다.
3. **Modularity** — 양호. 다만 **게이트 스크립트들은 모듈이 아니다** — 판정부를 재사용·검사 가능한
   형태로 꺼낼 수 있는 구조가 없고, 그것이 이번 backlog 의 주제다.
4. **Error handling** — CLI 는 JSON status 로 일관. 게이트 쪽은 이번에 **"실패"와 "측정 실패"** 를
   나누면서 한 단계 나아졌다.
5. **Test coverage** — unit/e2e/scenario 는 두텁다. **bash 게이트 4종은 커버리지 0** 이다.
   이번 세대가 그 공백을 문서화하고 backlog 로 올렸다.
6. **Documentation** — reap-guide / genome / environment / docs 사이트 5 로케일 유지.
   이번에 게이트 서술이 **실제 동작과 일치하도록** 좁혀졌다(여섯 세대 만에).
7. **Security** — 해당 사항 적음. 다만 이번에 **임시 프로젝트에만 권한을 부여**하고 사용자 `~/.claude/`
   는 읽기만 한다는 성질을 유지했다. V3 는 예외적으로 썼고 즉시 복구했다.
8. **Performance** — 해당 없음(게이트 비용은 성능이 아니라 예산 문제이며, fixture 로 라운드당
   $0.26 으로 묶었다).
9. **Deployment readiness** — 0.17.6 은 태그·발행만 남았다. 층2 가 이번에 **통과**했다.
10. **Code quality** — 게이트 스크립트가 4라운드 in-place 치환을 겪었으나 재래핑했고
    술어를 단일 소유로 바꿨다. 남은 냄새: 같은 node 인라인 블록이 여러 곳에 있다.
11. **User experience** — 개발자 UX 개선. **매 릴리즈마다 나오던 틀린 FAIL 이 사라졌다.**
12. **Visual verification** — 해당 없음 (CLI).
13. **Integration layer** — Claude Code / OpenCode 어댑터. 이번에 층2 가 **무엇을 검증하고
    무엇을 검증하지 않는지**가 처음으로 정확해졌다 — `@` import 와 hook 은 **미커버**다.
14. **Domain maturity** — genome/environment 가 코드와 동기화돼 있다.
15. **Governance compliance** — strictEdit 준수(계획 목록 밖 0), 회귀 4회 전부 `reap run back`,
    adapt 에서 backlog 생성 안 함. **위반 1건**: `environment/summary.md` 를 implementation 에서
    고쳤다가 evaluator 지적으로 되돌리고 reflect 에서 적용했다.
16. **Genome stability** — 91 세대에서 이번 변경은 **6줄 1개 절**. 매우 안정적.

## Embryo → Normal 전환 검토

| 기준 | 상태 |
|---|---|
| genome 수정 빈도 추세 | **감소.** 이번 세대는 6줄 1개 절. 최근 세대 대부분이 genome 무변경 |
| application.md 안정성 | **안정.** 정체성·아키텍처가 여러 세대 불변. 크기 규율에 걸릴 만큼 성숙 |
| abort 빈도 | **0.** 최근 abort 없음. 이번 세대의 회귀 4회는 abort 가 아니라 정상 micro-loop |
| vision/goals 명확성 | **명확.** Tree / Evaluator / Codex adapter 등 실행 가능한 항목 존재 |

**형식적 조건은 전부 충족한다.** 그럼에도 **전환을 제안하지 않는다** — 2026-03-26 사용자 판단
("REAP 자신이 self-evolving 중이므로 예기치 못한 genome 변경이 더 있을 수 있다")이 이번 세대에
**다시 입증됐다**: carrier 메커니즘 자체의 결함이 genome 규칙 추가를 요구했고, embryo 가 아니었다면
backlog 를 거쳐 다음 세대로 밀렸을 것이다. 0.18 의 지식 축 개편(idea/plan/milestone)이 genome 을
크게 건드릴 예정이므로 **그 이후가 전환 시점으로 적절하다.**

판단은 사용자 몫이다. 지금 전환하고 싶으시면 말씀해주시면 backlog 로 올린다.
