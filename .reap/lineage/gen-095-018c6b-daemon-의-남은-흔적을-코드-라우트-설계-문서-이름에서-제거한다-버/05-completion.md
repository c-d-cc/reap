# 05 Completion — gen-095-018c6b

**Goal**: daemon 의 남은 흔적을 코드·라우트·설계 문서·이름에서 제거한다 — 버전업 경로의 청소 코드는 남긴다

## Summary

gen-094 가 daemon 을 **사용자가 읽는 것**에서 지웠다면, 이 세대는 그 아래층이다 — 게이트·워크플로·
빌드 스크립트의 회고 주석, 아무도 가리키지 않는 라우트, 존재하지 않는 기능의 설계 문서, 그리고
읽는 코드가 0인 이름들.

사용자 지시가 방식을 정했다:

> *"D 역시 굳이 근거를 남길 필요가 없다. **「왜 그렇게 생겼는지」 라는 이유를 자꾸 작성하지 마라.**"*

폐기된 것과 **대조하는** 서술은 지우고, 지금 코드를 이해하는 데 필요한 사실(제약·불변식·외부 도구의
실측된 행동)만 남긴다. 애매하면 지운다.

### 승계 — 무엇을 받았고 무엇을 검증했나

직전 시도 `gen-095-6be9b6` 이 `--source-action hold` 로 abort 되어 워킹트리가 남았다. 승계 자체는
정당하나 **검증 없는 승계는 아니다** — 보존 대상 4건을 grep 으로 직접 재현하고 diff 를 전량 통독했다.

**그럼에도 5,364줄을 놓쳤다.** 통독 명령이 `git diff -- …` 였고 그것은 **staged 삭제를 보지 못한다.**
잔여물 grep 도 마찬가지다 — **삭제된 파일은 hit 을 내지 않는다.** 두 관측 수단이 같은 방향으로 눈이
멀었고, 유일하게 그 삭제를 언급하는 것은 `expect(existsSync(...)).toBe(false)` 즉 **삭제가 스스로를

## Lessons Learned

### 잘된 것 — 검사가 스스로 먼저 실패했다

승계된 sweep 검사가 착수 시점에 **11 pass / 3 fail** 이었고, 그 3 fail 이 정확히 잔여 작업 목록이었다.
검사를 만든 뒤 곧바로 통과를 보면 그 검사가 결함을 잡는지 알 수 없다 — 이 세대는 그 문제를 겪지
않았다. 신설한 `tests/` sweep 도 같은 규율로 만들었다: 만들고, 비-제외 파일에 이름을 심어 red 를 보고,
삭제한 fixture 를 인덱스+디스크에 되살려 red 를 한 번 더 보고, 복원했다.

**negative 를 6회 돌렸고 전부 red 를 확인한 뒤 복원했다** — tests sweep ×2 · genome 3파일 ×2 ·
로케일 개명 누락 · 라우트 문자열 불일치. 여기에 게이트 안에 프로브를 심어 확인한 것이 1회 더 있다.

### 개선할 것 — 이 세대의 결함은 전부 "내가 방금 한 일" 옆에 있었다

독립 검토 2라운드에서 blocker 5. **라운드 1 의 3건 중 1건은 내가 만든 것**이고, **라운드 2 의 2건은
둘 다 라운드 1 의 수정이 만들었거나 라운드 1 이 닿지 못한 곳**이었다. 여기에 내 자기점검이 찾은
off-by-one 3건과, **B1 을 고치는 도중 B1 이 재발한 1건**이 더 있다.

genome 의 *"라운드 N+1 의 결함은 라운드 N 의 수정 안에 있다"* 가 **네 번 성립했다.**

구체적으로:

1. **disjunct 하나를 지웠더니 남은 쪽이 무력해졌다.** `$FAKE_HOME/.reap/index` 와 실제 `.reap/.index`
   의 철자가 달라, FAIL 문구는 커버리지를 주장하는데 단언은 어떤 것에도 발화할 수 없었다.
   *지운 것*은 봤고 *남긴 것*은 읽지 않았다.
2. **§ 3 의 재현 명령을 내가 무효화해 놓고 다시 돌리지 않았다.** 라운드 1 의 다른 수정이 `src/` 아래
   마크다운을 고쳤고 그 명령이 그것을 잡는다. 자기점검에서 그 수정의 *수*는 다시 셌으면서,
   그 수정이 거짓으로 만든 *앞쪽 절*은 읽지 않았다.
3. **그리고 그것을 고치는 편집이 방금 정정한 인용을 다시 낡게 만들었다** — 줄 수가 2로 같아
   **수치만 봤으면 통과했을 것이다.** 명령을 다시 돌려서 잡았다.
4. **자기 기록의 수를 기억으로 적었다.** "회고 산문 7곳"(나열은 8개) · "`uninstall.ts` 3곳"(4곳) ·
   "`update.ts` 1곳"(2곳). 게이트도 테스트도 artifact 의 산술을 검사하지 않는다.

**교훈은 "더 조심하자"가 아니다.** 값을 바꾼 뒤 carrier 를 re-grep 하라는 규칙이 이미 있는데,
**artifact 에는 grep 할 표식이 없다.** 편집 후 물어야 할 질문은 *"내가 방금 바꾼 것 옆에 뭐가 있나"*
가 아니라 **"내가 방금 바꾼 것을 측정한 앞쪽 문장이 무엇인가"** 다.

### 자동 로드된 memory 가 한 버전 뒤였다

`CLAUDE.md` 가 `@` import 하는 memory 사본을 근거로 shortterm 에 *"0.17.6 은 아직 발행 전"* 이라고
썼다. **npm registry 에 물어보니 2026-08-20T15:21Z 에 이미 발행돼 있었다** (태그 `v0.17.6` 도 로컬에
있다). 자동 로드는 편하지만 **쓰인 시점의 사실**이며, 행동을 결정하기 전에 실물을 확인해야 한다.

### 잠복 결함을 하나 만들었다가 같은 세대에서 고쳤다

라운드 1 에 넣은 "인덱스에 있는데 디스크에 없다" throw 가, **`git ls-files` 가 비-ASCII 경로를
C-quote 하기 때문에** 한글 파일명에서 **틀린 원인**을 대며 터진다. 이 저장소의 backlog 파일명은
전부 한글이다. `-z` + NUL 분해로 고쳤고, 한글 프로브 파일로 2단 negative(무해할 때 throw 없음 /
유죄일 때 경로가 그대로 찍히며 red)를 확인했다.

### 스스로 잡은 것 셋 — 전부 "받지 말고 재라"의 실증이다

1. **`git ls-files` 가 비-ASCII 경로를 C-quote 한다.** 라운드 1 에 넣은 throw 가 그것을
   *"인덱스에 있는데 디스크에 없다 — 삭제를 스테이지하라"* 라는 **틀린 원인**으로 터뜨린다.
   **이 저장소는 backlog 파일명이 전부 한글이라 다음 backlog 하나가 그것을 터뜨렸을 것이다.**
   `-z` + NUL 분해로 고치고 한글 프로브로 2단 negative(무해할 때 throw 없음 / 유죄일 때 경로가
   그대로 찍히며 red)를 돌렸다. **negative 를 준비하다 실제로 만난 것**이지 예측한 것이 아니다.
2. **§ 3 을 무효화해 놓고 다시 돌리지 않았다.** 자기점검에서 그 수정의 *수*는 다시 셌으면서
   그 수정이 거짓으로 만든 *앞쪽 절*은 읽지 않았다. 그리고 **그것을 고치는 편집이 정정한 인용을
   다시 낡게 만들었다** — 두 번 모두 **줄 수가 2로 같아 수치만 봤으면 통과했을 것**이다.
3. **0.17.6 발행 여부를 registry 에 직접 물었다.** `CLAUDE.md` 가 `@` import 하는 memory 사본이
   한 버전 뒤였고 그것을 그대로 받아 *"아직 발행 전"* 이라고 썼다. npm 에 물으니
   **2026-08-20T15:21Z 에 이미 발행**돼 있었다. **"남의 문장을 받지 말고 재라"가 memory 에도
   적용된다** — 자동 로드는 편리하지만 쓰인 시점의 사실이다.

이 세대에서 **인계받은 문장이 틀린 것이 네 번**이다: 브리핑의 E 2파일(→1파일) ·
evaluator 의 tsc 5.7 vs 5.9(→둘 다 5.9.3) · memory 의 발행 상태 · 그리고
**evaluator·브리핑 양쪽이 말한 "한계 4 가 살아있다"**(→ gen-089 가 해소, `pipeline.ts:88,195`).
전부 재현해서 잡았다.

### genome — **적용함** (adapt, embryo)

`.reap/genome/evolution.md` § 검증 근거는 종류를 구분해 적는다 **에 한 문단 추가**:

> 수치 확인은 통과했을 것이다.

**자리는 접어서 만들었다.** 299줄에서 시작해 둘을 접었다:
