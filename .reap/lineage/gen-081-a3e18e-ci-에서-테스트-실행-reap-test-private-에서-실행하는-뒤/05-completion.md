# Completion

## Summary

**Goal**: CI 에서 테스트를 실행한다 — reap-test(private)에서 돌리는 뒤집기 구조.

**결과**: 완료. reap 의 main push 가 reap-test 워크플로를 발화하고 470 / 278 / 44 를 리눅스에서 0 fail 로 통과한다.

**핵심 결정**: 실행 주체를 뒤집었다. reap 이 public 이라 거기서 테스트를 돌리면 **공개 로그로 테스트셋이 새고 되돌릴 수 없다.** PAT 으로 submodule 을 당겨오는 방식(A안)은 기술적으로 되지만 private 으로 둔 목적 자체를 무너뜨린다.

**변경**:
- `reap/.github/workflows/ci.yml` — job `test` → `build` (테스트를 안 도는데 이름이 test 였다) + `dispatch-tests` 신설
- `reap-test/.github/workflows/test.yml` — 신규. checkout 2회로 `<reap>/tests/` 배치 재현
- `package.json` — `test:unit` 에 `--isolate`
- 테스트 3파일 — 머신 상태 의존 제거

**검증**: dispatch 전 경로 실측 (`reap 29d0a91` / `tests c27f5ac`). 토큰 교체 후에도 재확인. 공개 로그에 테스트 내용 0건.

## Lessons Learned

### 잘 된 것 — 로그 가시성을 선택 기준으로 삼았다

backlog 는 A안(PAT)을 "유일한 선택"으로 확정한 상태였다. 실행 직전에 **reap 이 public 이고 public 저장소의 Actions 로그는 누구나 본다**는 사실을 확인해 뒤집었다.

결정적이었던 것은 되돌릴 수 없다는 성질이다. 대부분의 잘못된 선택은 나중에 고치면 되지만 **이미 나간 로그는 회수할 수 없다.** 그래서 "일단 A로 해보고 문제되면 바꾸자"가 성립하지 않았다.

그리고 뒤집기가 **fork PR 문제까지 같이 없앴다.** A안은 fork 가 secret 을 못 받아 모든 외부 PR 이 red 가 되는 새 문제를 만들었을 것이다. 유저가 "fork PR 은 내가 수동 검증하면 되지 않냐"고 물었을 때 확인해보니, 뒤집기에서는 애초에 그 상황이 발생하지 않았다 — 내가 두 방식 공통의 문제인 것처럼 설명한 것이 부정확했다.

### 잘 된 것 — 디버깅 루프를 CI 밖으로 옮겼다

CI 왕복은 1회 ~1분 + 로그 조회다. 5회쯤 돌린 뒤 docker 리눅스 이미지로 옮겼고 반복이 수초로 줄었다.

다만 **첫 이미지 선택이 틀렸다.** `oven/bun` 에 git 이 없어서 전혀 다른 원인의 실패를 보고 있었고, 하마터면 "mock 이 원인"이라는 잘못된 결론을 굳힐 뻔했다. 재현 환경이 대상과 어디까지 같은지 확인하지 않으면 **변수를 줄이는 게 아니라 하나 더 만드는 것**이다.

### 개선점 — 위험 예측이 정확히 반대였다

| 스위트 | 계획의 예측 | 실제 |
|---|---|---|
| unit | 낮음 | **잠복 버그 3종** |
| daemon e2e | **높음** | 무수정 통과 |

네이티브 빌드·WASM·포트 바인딩이라는 "복잡해 보이는" 요소에 위험을 배정했고, "외부 의존 없음"이라는 이유로 unit 을 안전하다고 봤다. 실제 위험은 복잡도가 아니라 **한 번도 다른 환경에서 돌아본 적 없다**는 데 있었다.

다만 단계적 도입 자체는 값을 했다. 예측이 틀려도 **실패가 어느 스위트에서 왔는지 즉시 귀속**됐다. 위험 예측의 정확도보다 배치 크기를 줄이는 쪽이 확실한 투자였다.

### 개선점 — 해법 후보를 실측으로 걸렀어야 더 빨랐다

mock 누수 해법으로 `afterAll` 복구를 먼저 시도했고 CI 한 바퀴를 써서 무효임을 확인했다. bun 이 모든 파일을 로드한 뒤 실행한다는 것은 **처음 실패 로그에서 파일 그룹이 순차 출력되는 것을 보고 순차 로드로 단정한 결과**였다. 순차 출력 ≠ 순차 로드다.

가정을 세운 지점에서 한 번 더 확인했으면 후보 하나를 건너뛸 수 있었다.

### 알게 된 것 — green 은 환경 하나의 표본일 뿐이다

세 결함 모두 "로컬에서 470-0" 인 상태에서 존재했다. 특히 mock 누수는 **bun 의 디렉토리 순회 순서에 우연히 기대어** 통과하고 있었다 — macOS 는 통과, 리눅스는 실패. 코드도 테스트도 바뀌지 않았는데 결과가 갈렸다.

"통과한다"가 증거가 되려면 **어디서 통과했는지**가 함께 있어야 한다.
