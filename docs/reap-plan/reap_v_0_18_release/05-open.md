## Q1. reap.cc 문서 사이트의 거취

| 선택지 | 무슨 일이 생기나 |
|---|---|
| A. v0.18에 새 문서 사이트를 짓는다 (추천 아님 — 규모) | 24쪽 × 5로케일을 다시 쓴다. 0.18.0 발행이 그만큼 늦는다 |
| B. **0.18.0은 README(+`docs/guide/` 마크다운)로 내보내고, 사이트는 v0.17 것을 유지한다** (추천) | main merge 시 `docs/`·`docs.yml`을 v0.17에서 살려 두거나 사이트를 별도 브랜치(`gh-pages` 성격)로 옮긴다. 사이트가 0.17 내용을 계속 보여주므로 머리말에 "0.18은 README" 안내 한 줄이 필요하다 |

## Q2. 언어 — v0.18은 한국어 전용이다

**답: B — CLI 문자열과 skill을 en으로 갈고 ko를 번역 층으로.** (사람, 2026-09-04) → G9. genome의 "사용자에게 보이는 문자열은 한국어"가 바뀐다

**사실:** genome이 "사용자에게 보이는 문자열은 한국어"로 정했고 CLI 출력·skill 본문·map.md 전부 한국어다. v0.17은 CLI 4개 언어, README 5로케일, 사이트 5로케일이었다. 0.17의 en/ja/zh/de 사용자가 0.18로 오면 **도구가 한국어로 말한다.**

| 선택지 | 무슨 일이 생기나 |
|---|---|
| A. **0.18.0은 한국어로 내보내고 README만 영어 병기** (추천 — 설계 결정 유지, 비용 최소) | 비한국어 사용자에게는 사실상 0.18이 없다. 0.17.8 다리 안내문에 그 사실을 적어야 한다 |
| B. CLI 문자열과 skill을 en으로 통째로 갈고 ko를 번역 층으로 | 문자열 전수 이관 + skill 10종 번역. 발행이 늦고, "skill 본문이 곧 규율"인 구조에서 번역판이 어긋날 위험 |

## Q3. 테스트 공개 여부

**사실:** v0.17은 테스트를 private 리포(`c-d-cc/reap-test`) submodule로 빼고 CI가 dispatch로 돌린다("공개 로그에 테스트 이름이 찍히면 되돌릴 수 없다"). v0.18은 `tests/` 15파일이 리포 안에 있다(스냅샷이 개발 리포의 것을 그대로 실었다). c-d-cc/reap은 공개 리포다.

| 선택지 | 무슨 일이 생기나 |

| B. reap-test에 `v0.18` 브랜치를 만들어 submodule로 | v0.17 방식 유지. 개발 루프에 submodule 마찰([[feedback_tests_submodule]])이 돌아온다 |

## Q4. subagent 실행자 — 더 나은 agentic workflow 후보

**답: B — evolve에 위임 모드를 더한다.** (사람, 2026-09-04) → G12

**사실:** v0.17 `/reap.evolve`의 핵심 가치는 **세대 전체를 subagent가 수행해 주 세션의 컨텍스트를 보호**하는 것이었다(reap.evolve.md: "subagent가 유일한 실행자"). v0.18 `evolve`는 주 세션이 직접 일한다 — 흐름은 판단이고 판단은 skill의 것이라는 원칙의 결과이며, `.session` 바인딩이 **디렉토리 단위**라 같은 cwd의 subagent가 세대를 열면 바인딩이 겹친다(07-orchestrate "같은 디렉토리에서 세션 둘은 지원하지 않는다").

이 loop를 수행하며 실제로 겪은 것: orchestrator 세션이 조사·probe를 subagent에 맡기고 결론만 받는 패턴이 컨텍스트를 확실히 아낀다. 그런데 REAP에는 "한 세대를 subagent에게 통째로 맡기는" 절차가 없다 — orchestrate는 **세션** 간 조율(worktree 분리)만 다룬다.

| 선택지 | 무슨 일이 생기나 |
|---|---|
| A. 지금은 안 한다 — 0.18.0 뒤 실사용 fitness에서 다시 본다 (추천 — 방향 질문이라 실측 없이 정하지 않는다) | 0.17 사용자는 "evolve 한 번에 자율 실행"을 잃은 채 0.18을 받는다. README가 그 차이를 적는다 |
| B. `evolve`에 "위임 모드"를 더한다 — 주 세션이 세대를 열고 Intent를 적은 뒤 subagent가 일하고, 주 세션이 `complete` | `.session`은 주 세션 것이라 바인딩 충돌이 없다. skill 산문 추가만으로 되지만, "REAP는 관여하지 않는다"는 구간에 REAP가 관여하는 것이라 원칙 확인이 필요하다 |
| C. worktree 기반 orchestrate로 푼다 | 이미 있는 길. 다만 세대 하나에 worktree 하나는 무겁다 |

## Q5. reap2 GitHub 리포와 마켓플레이스 `reap2` 항목

**답: A — 마켓플레이스 항목을 `reap`으로 교체, reap2 항목 삭제, reap2 리포 archive.** (사람, 2026-09-04) → ms-019 task 4. 리포 archive는 GitHub 설정이라 사람이 한다

**사실:** `c-d-cc/reap2`(개발 리포, 68커밋 미푸시)가 GitHub에 있고, `c-d-cc/plugins`가 그것을 submodule `plugins/reap2`로 실어 `reap2`라는 이름의 플러그인을 노출한다. v0.18 플러그인 이름은 `reap`이다.

| 선택지 | 무슨 일이 생기나 |
|---|---|
| A. **마켓플레이스 항목을 `reap`(submodule `plugins/reap` → c-d-cc/reap)으로 교체하고 reap2 항목은 지운다. reap2 리포는 archive** (추천) | `reap2`를 설치한 사람이 있다면 그쪽은 갱신이 끊긴다 — 사내 마켓플레이스라 영향 범위를 사람이 안다 |
