# 지식 레이어

## plan source

**REAP는 기획을 쓴다.** 쓰는 자리가 plan source이고, 쓰는 사이클이 loop다(`02-flow.md`의 `plan 축의 단위는 loop다`). 프로토콜은 넷이다.

| | 무엇 | 어디 |
|---|---|---|
| **등록** | 어느 소스를 쓰는가 | `make plan-source` → `plan/sources.yml` |
| **읽기** | 그 소스를 어떻게 읽는가 | `plan sources` · `plan convention` · `conventions/<ps-id>-<slug>.md` |
| **쓰기** | loop가 그 소스에 쓴다 | `loop` skill의 판단 — 어느 소스에, 새로 쓸지 고칠지, 규약에 맞춰 |
| **인용** | 무엇을 근거로 삼았는가 | milestone의 `refs: <ps-id>:<경로>` |

**한때 쓰기를 밖으로 내보냈다.** `gen-0045-plan`이 기획을 별도 플러그인(`reap-plan`)의 것으로 두고 REAP는 소비만 하기로 했는데, 사람이 되돌렸다(`loop-0001`). 그때 있던 `make issue`(기획에 고칠 것을 돌려보내는 길)는 **함께 사라졌다** — 자기가 쓰는 기획에 자기가 issue를 낼 이유가 없다. 고칠 것은 loop가 고친다.

### 인용은 파일 경로까지다

`refs`는 `<ps-id>:<상대경로>`이고 **그 문서 안에 무엇이 있는지는 모른다.** 기획이 Capability·Feature·Requirement 같은 항목 구조를 갖더라도 REAP는 그것을 읽지 않는다.

**일부러 약하게 둔다.** 항목 단위로 인용하려면 기획 쪽 구조를 REAP가 알아야 하고, 그러면 **REAP가 작업의 모양을 결정하게 된다** — `genome/application.md`가 금한 것이다. 기획의 계층은 프로젝트마다 다르고, 그것을 아는 것은 그 소스의 `conventions/`와 loop의 일이지 도구의 일이 아니다.

대가는 분명하다: *"이 milestone이 그 문서의 어느 대목에서 나왔는가"*는 `refs`가 아니라 **milestone 본문의 `Background`**가 담는다. 검색되지 않는 자리다.

### 레지스트리

```yaml
# .reap/plan/sources.yml
sources:
  - id: ps-a3f8c2
    root: ../product-docs        # 리포 밖 가능. 절대경로도 가능
    role: 제품 기획
    convention: conventions/ps-a3f8c2.md
  - id: ps-77b1e0
    root: ./docs/design
    role: 설계 문서
    convention: conventions/ps-77b1e0.md
```

### 규약 문서

`conventions/<ps-id>-<slug>.md`는 **agent가 갱신하는 문서**다. 처음에는 사람이 소스를 등록하며 한두 줄 적고, 이후 loop가 그 소스를 실제로 다루면서 알게 된 것을 채워 나간다.

담는 것: 이 소스의 디렉토리 구조와 각 부분의 의미, **어디부터 읽어야 하는지**, 무엇이 authoritative이고 무엇이 참고인지, **새 문서를 어디에 어떤 형식으로 쓰는지, 기존 문서를 고칠 때의 관례**, 하지 말아야 할 것.

**되먹임이 실제로 일어나는지가 이 문서의 시험이다.** 이 리포의 `ps-4f2a91-reap.md`는 등록 이후 내용이 안 바뀌었다 — loop가 돌기 시작하면 달라져야 하고, 안 달라지면 자리의 문제다.

### plan 인용

milestone은 `<ps-id>:<상대경로>[#<앵커>]` 형식으로 plan을 인용한다.

```yaml
refs:
  - ps-a3f8c2:prd/auth.md#세션관리
  - ps-77b1e0:adr/0012.md
```

`doctor`는 파일시스템 소스에 한해 이 참조가 실제 파일을 가리키는지 검사한다. 앵커까지는 검사하지 않는다 — 마크다운 헤딩은 자유롭게 바뀌고, 검사하면 정상 동작을 결함으로 보고하게 된다.

**가리키던 파일이 사라졌으면 `doctor`가 보고한다.** 기획이 문서를 지웠는데 그것을 근거로 삼은 milestone이 있다는 뜻이고, 고칠지는 loop에서 사람과 정한다. **REAP가 `refs`를 조용히 고치지 않는다** — 고치면 어느 근거로 만들었는지가 사라진다.

## idea — 아직 단단하지 않은 지식의 자리


genome은 확정된 처방이고, environment는 확인된 사실이고, plan은 만들려는 것의 의도다. **셋 다 단단한 지식을 위한 자리다.** 그런데 프로젝트에는 아직 단단하지 않은 것이 계속 생긴다 — 조사해뒀지만 결론은 없는 것, 이상한데 아직 뭔지 모르는 관찰, 언젠가 쓸지도 모르는 외부 자료.

둘 자리가 없으면 셋 중 하나가 일어난다. memory에 밀어넣거나(교훈이 아닌 것이 교훈 자리를 차지한다), 설계 문서로 승격시키거나(**모호한 것을 단단한 자리에 두면 단단해 보인다** — 다음 세션이 결정된 것으로 읽는다), 그냥 버린다(조사 비용이 사라지고 다음에 같은 질문이 오면 처음부터 다시 한다).

### 구조

```
.reap/idea/
  research/     조사 결과 — 지금 결론은 없지만 다시 찾지 않게 해주는 것
  freememo/     자유 메모 — 형식 없음. 떠오른 것, 미완결 관찰, 판단 보류
  files/        참고자료 — 외부에서 가져온 발췌·링크·스펙 조각
```

| 하위 | 요구 형식 | 졸업하면 어디로 |
|---|---|---|
| `research/` | 출처 + 확인 날짜 + 1차/2차 구분, 졸업 조건 | plan source (결론이 서면) · backlog (할 일이 되면) |
| `freememo/` | **없음** | 어디로든, 또는 삭제 |
| `files/` | 출처 + 가져온 날짜, 졸업 조건 | `environment/resources/` (실제로 채택되면) |

`freememo/`만 형식 요구가 없다. **아무 요구도 없는 자리가 하나는 있어야 사람이 쓴다** — 형식을 요구하면 안 쓰고, 안 쓰면 이 기능은 없는 것과 같다. 대신 형식이 없으므로 가장 먼저 정리 대상이 된다.

### 경계

- **idea vs plan** — plan은 만들려는 것에 대한 의도다. idea는 아직 어느 자리에도 못 가는 재료다. 조사에서 결론이 서면 plan source로 졸업한다.
- **idea/files vs environment/resources** — **채택 여부**가 가른다. 지금 이 프로젝트가 쓰고 있는 것의 스펙이면 `environment/resources/`, 쓸지도 모르는 것의 자료면 `idea/files/`. 채택되는 순간 이동한다.
- **idea/freememo vs milestone handoff** — 다음 세션에 **필요한** 것은 `handoff.md`, 필요할지 **모르는** 것이 `freememo/`. 이 구분이 무너지면 freememo가 handoff의 우회로가 되고, 그러면 handoff는 아무도 안 읽는 파일이 된다.
- **idea vs 세션 임시 디렉토리** — 임시 디렉토리는 세션 수명의 중간 산출물이고, idea는 프로젝트 수명의 미완결 **지식**이다.

### 쓰레기통이 되지 않게 하는 장치

idea의 실패 모드는 명확하다. **아무 제약이 없으면 무한히 쌓이고, 쌓이면 아무도 안 읽고, 안 읽으면 없는 것과 같다.** 진입 장벽이 낮은 만큼 memory보다 빨리 온다.

**각 문서가 자기 졸업 조건을 갖는다** (`freememo/` 제외). 템플릿이 두 줄을 요구한다: 무엇이 미정인가, 무엇이 정해지면 졸업하는가. "언젠가 쓸지도"는 영원히 남을 핑계가 되므로, 나가는 문을 문서가 스스로 갖고 있어야 한다 — milestone의 종료 조건과 같은 사고다.

`make`는 빈칸이어도 거부하지 않는다. 거부는 흐름 제어이고, REAP에서 흐름은 skill의 것이다. 대신 **`doctor`가 사후에 보고한다**: 졸업 조건이 빈 research·files 문서, 출처나 확인 날짜가 없는 문서, 오래 방치된 항목.

### 자동 로드하지 않는다

미완결 자료가 매 세션 context를 차지하면 확정된 지식의 자리를 밀어낸다. **본문도 목록도 주입하지 않는다.** `ctx`의 상태 줄이 디렉토리 위치를 알리고, 무엇이 있는지 보려면 agent가 그것을 읽는다.

REAP은 여기서 "index 파일을 누가 갱신하는가"라는 문제를 만났다 — 정적 import로는 디렉토리를 통째로 넣을 수 없어 index 파일이 필요했고, 수기 갱신은 반드시 어긋난다. **REAP에는 그 문제가 없다.** 디렉토리를 읽는 것이 곧 목록이므로 index 파일 자체가 존재하지 않는다.

### git

`freememo/`를 포함해 **전부 커밋한다.** 병렬 worktree에서는 커밋되지 않은 파일이 다른 세션에 도달하지 않으므로, 예외를 두면 그 하위만 조용히 공유되지 않는다. 하위별로 다르게 취급하는 규칙보다 단순한 규칙 하나가 낫다.

### 명령

```bash
reap make idea --kind research|freememo|file --title "<t>" [--slug <s>]
```

id는 `idea-a3f8c2` 형태의 해시다. 졸업하거나 버려지는 것이라 번호를 영구히 점유할 이유가 없다.

## memory — 나가는 문이 있어야 한다


`lessons.md`는 프로젝트가 사는 동안 계속 자란다. 그리고 **자라기만 하는 문서는 언젠가 아무도 읽지 않는다.** idea에 졸업 조건을 요구한 것과 같은 문제이며, 여기서는 더 조용하게 온다 — idea는 미완결이라는 자각이 있지만 lessons는 "확정된 교훈"이라 지울 이유를 아무도 찾지 않는다.

### lessons는 대기실이다

**반복 확인된 교훈은 `genome/evolution.md`의 규칙으로 졸업하고, lessons에서 지운다.** 한 번 겪은 것은 관찰이고, 여러 번 겪은 것은 규칙이다. 규칙이 된 것을 두 곳에 두면 어긋나고, 어긋난 쪽을 다음 세대가 읽는다.

더 이상 유효하지 않은 것도 지운다. 기술 선택이 바뀌었거나 그 실수를 만들 수 있는 코드가 사라졌으면 그 교훈은 이제 잡음이다.

### 제목이 결론이어야 한다

주입되지 않으므로 agent는 파일을 열어 훑는다. 그때 제목만 읽고도 무엇에 관한 교훈인지 알 수 있어야 한다 — "섹션 번호로 문서를 인용하면 밀린다"는 제목 자체가 교훈이고, "문서 인용에 대하여"는 열어봐야 안다.

### 검사하지 않는다

같은 주제가 lessons와 genome에 함께 있는지는 **확정적으로 검사할 수 없다.** 자유 산문이고, 같은 규칙이 다른 말로 쓰이기 때문이다. `doctor`는 항목 수와 파일 크기가 안내선을 넘었을 때만 보고한다 — 그것이 곧 "졸업시킬 때가 됐다"는 신호다.

## 코드를 아는 세 층

REAP가 코드에 대해 아는 것은 셋으로 갈린다. **무엇이 어느 층의 것인지 헷갈리면 그 지식은 잘못된 자리에 있고, 잘못된 자리에 있는 지식은 낡는 것이 안 보인다.**

| 층 | 무엇을 아는가 | 누가 만드나 | 최신성 |
|---|---|---|---|
| **index** | 무엇이 존재하고 무엇이 무엇을 부르는가 — 심볼과 `CALLS`·`IMPORTS` | 파서 | 커밋 단위로 자동 |
| **`environment/source-map.md`** | 각 모듈이 **무엇을 위한 것이고 왜 그렇게 생겼는가** | agent | 손으로 |
| **carrier 표식** | 한 사실을 **아는 곳이 어디어디인가** | 사람 | 표식 자체 |

**경계가 날카롭다.** index는 파서가 볼 수 있는 것만 안다. `source-map.md`는 **의도**를 안다 — 파서가 못 보는 것이고, 그래서 index가 있어도 이 문서가 필요하다. carrier는 **파서도 산문도 못 잇는 연결**을 안다.

셋은 대체 관계가 아니다. *"이건 어디 정의됐나"*는 index가, *"이 모듈은 왜 있나"*는 `source-map.md`가, *"이걸 고치면 어디를 같이 고쳐야 하나"*는 carrier가 답한다.

### index — 변경 단위는 커밋이다

인덱스는 **자기가 서술하는 커밋 SHA를 기록한다.** 무엇을 다시 파싱할지는 `git diff` 하나로 정해지고, 아예 갱신할지 말지는 문자열 비교 하나다. 상주 프로세스도 파일 감시자도 없다.

**질의가 스스로 갱신한다.** `HEAD`가 움직였으면 — 커밋했든 브랜치를 바꿨든 리베이스했든 — 다음 질의가 먼저 인덱스를 올린 뒤 답한다. REAP가 먼저 갱신하는 곳은 **자기가 방금 커밋을 만든 자리**뿐이다.

**커밋 안 된 작업은 인덱스에 없다.** 위의 전부를 사는 대가다. 방금 쓰고 커밋 안 한 심볼은 `search`가 못 찾고 방금 만든 파일은 `impact`에 안 나온다 — 그런 것은 `grep`으로 찾는다. `status`가 인덱스가 서술하는 커밋을 항상 내므로 **그 간극이 언제 문제가 되는지 보인다.**

**git 저장소가 없으면 인덱싱하지 않는다.** 인덱스를 매달 커밋이 없으므로, 서술할 수 없는 것을 인덱싱하는 대신 그렇게 말한다.

### index — 해석률을 화면에 낸다

`status`가 내는 것 중 **가장 중요한 줄은 import 해석률**이다. `impact`가 아는 것은 전부 해석된 import edge에서 오므로, **해석률이 낮으면 빈 blast radius는 "없음"이 아니라 "모름"이다.**

이것을 화면에 안 내면 조용히 틀린다. `./x.js` 지정자를 그것을 만드는 `x.ts`로 잇지 못하는 인덱서는 **표준 TypeScript 프로젝트에서 import를 하나도 해석하지 못하는데**, "인덱싱이 돌았는가"만 묻는 검사는 그때도 전부 초록이다. **돌았는지가 아니라 무엇을 아는지를 재야 한다.**

### index — 하지 않는 것

`impact`는 파일 사이 import를 걷는다. **커뮤니티 탐지와 프로세스 추적은 의도적으로 두지 않는다.**

REAP에서 둘 다 지어봤고 둘 다 못 쓸 것이 나왔다. 앞의 것은 다른 이름의 연결 요소여서 응집도 점수가 **상수 1.00**이었고, 뒤의 것은 호출자를 못 찾은 함수를 **전부 진입점이라고 불렀다.** 둘을 내보내는 것은 **작동하는 분석 하나 대신 아무도 손댈 수 없는 분석 셋을 내는 일**이다.

호출 해석이 이름 기반 휴리스틱이라는 한계도 남는다 — 타입 해석 없이 동명이인을 이름과 위치로 고르므로 오버로드와 동적 디스패치에서 틀린다. **의미 기반 인덱서(SCIP 등)로 올리는 길은 있지만 사용자 저장소에서 빌드가 가능해야 한다는 요구를 낳고, 그것은 패키징으로 없앨 수 있는 비용이 아니다.** 실사용자가 정확도에 부딪히기 전에는 짓지 않는다.

### index — 파서는 바이너리가 싣는다

**설치 즉시 동작해야 한다.** 따로 설치할 것도, 띄울 프로세스도 없다. 파서를 사용자 환경에서 찾는 모델은 *"있으면 쓰고 없으면 꺼진다"*가 되고, 그러면 **index가 있다는 전제로 쓴 skill이 어떤 사용자에게는 조용히 안 돈다.**

**싣는 방식** — `import x from "….wasm" with { type: "file" }`. `bun build --compile`이 바이너리에 넣고 런타임에 `/$bunfs/…` 경로를 준다(probe, `gen-0058`). tag 질의(`*.scm`)는 텍스트 임포트다. **언어 15개**(TS·TSX·JS·Python·Go·Rust·Java·Kotlin·C#·C·C++·Ruby·PHP·Swift·Dart)를 전부 싣고 바이너리는 61MB → **89MB**다. 줄이지 않는다 — REAP 자신은 TS 하나지만 index는 배포 대상 프로젝트를 위한 것이고, 빠진 언어는 그 프로젝트에서 조용히 0 심볼이 된다. 상대 import 해석은 JS/TS(`./x.js`→`x.ts` 포함)와 Python만이다 — 나머지 언어는 심볼·CALLS는 되고 IMPORTS·impact는 안 된다. **인덱스는 `.reap/.index/`에 살고 `init`이 gitignore에 넣는다.**

## 결정 로그를 두지 않는다

**정해진 것은 그것이 규율할 자리에 반영되어야만 살아남는다.** spec이거나, `genome/`이거나, `map.md`다. 반영하지 않았다면 안 정해진 것이다. **`reap decide`도 `decisions.md`도 두지 않는다.**

결정 로그는 매력적이다 — 무엇을 언제 왜 정했는지가 한 줄로 남고, 다음 세대가 같은 것을 다시 정하지 않는다. 두 milestone 동안 실제로 그렇게 돌았고 27줄이 쌓였다. 그런데 그 27줄을 나중에 훑어보니 **milestone 안에서만 유효한 것은 사실상 없었다.** 전부 프로젝트를 계속 규율하는 것이었고, 그 말은 곧 **spec에 있어야 할 것이 spec 밖에 있었다**는 뜻이다.

그것이 무는 대가는 `genome/application.md`가 이미 적어둔 것과 같다 — **두 곳에 있으면 어긋나고, 어긋난 쪽을 다음 세대가 읽는다.** 실제로 그렇게 됐다. `02-flow.md`의 도식이 `06-agent.md`의 산문과 어긋난 채 두 milestone을 버텼고, 어느 쪽이 참인지는 spec만 봐서는 정할 수 없었다 — 닫힌 milestone의 결정 로그를 꺼내야 했다. 로그가 그 어긋남을 **막은 것이 아니라 견딜 만하게 만들어** 오래 살렸다.

**그리고 로그는 자란다.** 프로젝트가 커질수록 항목이 늘고, 늘수록 서로 어긋나며, 어긋난 것을 아무도 세지 않는다. 반영은 그렇지 않다 — 같은 자리를 고치는 일이므로 어긋남이 **고칠 때 드러난다.** 그것이 정합성을 지키는 유일한 장치다.

잃는 것은 출처다. 언제 누가 왜 정했는지는 로그가 아니라 **git이 갖는다.** `git log -L`로 한 줄의 이력을 끝까지 따라갈 수 있고, 그것이 로그보다 정확하다 — 로그는 사람이 적기를 잊을 수 있지만 커밋은 그럴 수 없다.

## 차용하는 개념


REAP의 구현을 가져오지 않는다. 개념만 참조해 필요에 맞게 새로 만든다.

**genome** — 규범 지식. 어떻게 만들어야 하는가. `application.md`(제품 정체성과 아키텍처), `evolution.md`(AI 행동 규칙), `invariants.md`(사람만 수정하는 절대 제약). REAP는 genome을 도구로 강제하지 않는다. 불변성 규칙은 `evolution.md` 자신이 기술하고 agent가 따른다.

**environment** — 현상 지식. 지금 무엇이 있는가. `summary.md`가 항상 로드되고, 나머지는 필요할 때 읽는다.

**memory** — milestone을 가로지르는 맥락. `lessons.md`(프로젝트 전역 교훈) 하나다. **결론 안 난 물음은 여기 두지 않는다** — 그것은 `idea/research/`의 자리다. 물음은 닫히는 것이고 교훈은 쌓이는 것이라, 한 파일에 섞으면 어느 쪽도 정리되지 않는다. REAP의 3-tier에서 shortterm의 역할은 milestone의 `handoff.md`가 가져간다. midterm에 해당하는 것은 두지 않는다 — 아래 `결정 로그를 두지 않는다`를 본다. **주입되지 않고 `ctx`의 상태 줄이 위치만 알린다** — 누적되는 문서이기 때문이다. 앞의 `memory — 나가는 문이 있어야 한다`를 본다.

**carrier marker** — **한 사실을 아는 곳을 전부 찾는 수단.** 위의 `코드를 아는 세 층` 중 셋째다. 값이 여러 곳에 알려질 때 그 자리마다 표식을 남겨두면, 그 사실을 고치기 전에 `grep` 한 번으로 나머지를 찾는다.

```ts
// reap:carrier-a1b2c3-claude-code-commands-path
export function claudeCodeCommandsDir(...) { ... }
```
```markdown
<!-- reap:carrier-a1b2c3-claude-code-commands-path -->
```

**이것이 푸는 것은 중복 자체가 아니라 중복을 못 찾는 것이다.** 값을 공유할 수 있으면 공유하고 규범 소유자를 정할 수 있으면 정하되, **어느 쪽이든 먼저 어디가 그 사실을 아는지 알아야 한다.** 목록을 따로 두는 방법은 REAP에서 실패했다 — 목록은 그것이 있다는 걸 기억하는 사람이 관리해야 하고, 목록에 없는 자리가 낡는다. **그래서 파일이 스스로 선언한다.**

**id는 `carrier-<hash6>`이고 표식은 `reap:<id>-<slug>`다.** id 부분이 `bk-a3f8c2-token-rotation-retry`나 `idea-a3f8c2-oauth-device-flow`와 **똑같은 형식이다** — 괄호로 감싸지 않는다. 접두사가 이미 계열을 말하므로 감싸는 것이 하는 일이 없고, **감싸면 REAP에서 id가 생긴 모양이 이것 하나만 달라진다.**

**`reap:` 이름공간은 붙인다.** 이것만 파일 이름이 아니라 **남의 소스 안 주석**으로 들어가기 때문이다. 그 파일은 REAP를 모르고, `carrier-`로 시작하는 낱말이 그 프로젝트에 이미 있을 수 있다. 이름공간이 그 자리에서 "이건 REAP 것"이라고 말한다.

**해시가 필요한 이유는 충돌 감지다.** 같은 slug를 받은 두 사실은 `grep`이 무관한 파일을 함께 물어오게 만들고, 그것이 둘이라는 것을 아무것도 말해주지 않는다. **해시는 발급할 때 무작위로 뽑고 slug에서 유도하지 않는다** — 이름에서 유도한 id는 이름이 바뀔 때 함께 바뀌고, 그것이 id가 막으려는 바로 그 일이다.

찾는 방법도 다른 id와 같다. `grep -rn "carrier-a1b2c3" .`가 그 사실을 아는 곳 전부를 낸다.

**산문 속 언급은 표식이 아니다.** 규약을 설명하는 글은 `reap:carrier-<hash6>-<slug>`처럼 꺾쇠를 쓰고, `<`·`>`·공백이 든 것은 세지 않는다.

**backlog** — 이월 항목. 지금 하지 않기로 한 것을 기록한다. REAP처럼 특정 단계에서 소비되도록 강제되지 않는다. `type`은 관례이며 `mark backlog --consumed`는 표시만 하고 소비 시점을 정하지 않는다. **나가는 문은 `cleanup`이 연다** — `life/backlog/`도 작업 세트이므로 참고 가치가 다한 항목은 `archive/backlog/`로 내려간다. 상태와 위치는 다른 질문이다. 그리고 **backlog 항목은 exec generation의 근거가 된다**(`02-flow.md`) — 항목 하나가 경계 하나다.
