# 개념과 원칙

## 무엇을 만드는가


REAP는 AI와 사람이 소프트웨어를 함께 진화시키기 위한 **규약과 도구의 집합**이다. 전작 REAP과 달리 파이프라인 실행기가 아니다.

한 문장으로: **REAP는 작업의 모양을 결정하지 않는다. 작업이 쓸 수 있는 도구와, 무엇을 어디에 저장할지에 대한 규약을 제공한다.**

REAP과의 호환성은 고려하지 않는다. 마이그레이션은 REAP가 완성된 뒤 별도로 다룬다.

## REAP에서 무엇이 바뀌는가


| | REAP | REAP | 왜 |
|---|---|---|---|
| 성격 | 파이프라인 실행기 | 규약 + 도구 제공자 | 5단계 강제를 유지하려 스크립트와 서명 잠금을 계속 늘려야 했다 |
| 작업 단위 | generation 하나 | plan · exec · fix 세 유형 | 실행보다 기획·분해가 더 의미 있는 관리 요소였다 |
| lifecycle | 5단계 고정 + 서명 잠금 | 없음 | 경직성이 확장을 막았다 |
| 흐름 제어 | CLI가 소유 | skill이 소유 | 판단을 스크립트로 강제하려다 스크립트가 늘고, 늘어난 스크립트가 다시 경직성이 됐다 |
| context 생성 단위 | generation | milestone | 세대마다 맥락을 다시 쌓는 것은 낭비였다 |
| 기획 산출물 | `.reap/vision/` 안 | 리포 밖일 수 있는 **등록된 plan source** | 제품 기획은 REAP 소유물이 아니다 |
| 병렬 협업 | merge lifecycle | orchestrate | 브랜치 병합이 아니라 세션 간 조율이 실제 문제였다 |
| 인간 평가 | 매 generation | milestone 종료 시 | 매 세대 사람이 막아서는 마찰이 자율성과 충돌했다 |

## 개념 모델


두 개의 진화 축이 있고, 한쪽의 산출이 다른 쪽의 입력이 된다.

```
plan sources (외부, 여러 곳)
      ^
      | evolve
      |
  loop  (plan 축의 사이클 — generation이 아니다)
      |
      | carve out
      v
  milestone  --+-- exec generation --+
               |                     | evolve
               +-- exec generation --+--> civilization (소스코드)

  fix generation (milestone 무소속) ------> civilization
```

**plan** — 제품을 만들기 위한 모든 생각. 기획, 계획, 설계, 아이디어. **소스코드에 준하는 1급 artifact set**으로 다룬다. REAP 디렉토리 안에 강제되지 않으며, 리포지토리 밖일 수도 여러 곳일 수도 있다. REAP는 각 plan source를 **어떻게 읽고 어떻게 쓰는지에 대한 규약을 기억**한다.

**milestone** — plan에서 잘라낸 실행 가능한 단위. 경계와 종료 조건을 가진다. **공유 context가 사는 단위**이며, 인간의 fitness 평가를 받는 단위다.

**generation** — 작업 사이클. 세 유형이 있고, **무엇을 하는가**로 갈린다.

| | 무엇을 | milestone |
|---|---|---|
| **loop** | 새 의도를 만든다 — plan source를 진화시킨다. 산출물이 자리를 찾으면 닫힌다(milestone을 낳는 것이 보통) | generation이 아니다. `life/loops/` |
| **exec generation** | 새 의도를 실현한다 — 소스코드를 진화시킨다 | **반드시 소속** |
| **fix generation** | 이미 있는 의도로 되돌린다 — 버그, 깨진 빌드, 낡은 의존성, 오타 | 무소속 |

**fix가 milestone을 갖지 않는 이유는 작아서가 아니다.** milestone은 새 의도에 경계를 주는 장치인데,
되돌리는 일은 새 의도를 만들지 않는다 — 그 경계는 이미 어딘가에 존재하는 원래 의도다. 자세한 것은
[fix는 예외가 아니다](02-flow.md)에 있다.

**크기는 기준이 아니다.** 작은 새 기능은 fix가 아니라 exec다.

**civilization** — `.reap/` 밖의 소스코드와 산출물. exec generation과 fix generation이 손대는 대상.

### 원칙

1. **REAP는 흐름을 제어하지 않는다.** 세대 내부의 탐색·계획·구현 순서는 물론, 언제 열고 언제 닫을지도 skill이 기술하고 agent가 판단한다. 통과·차단하는 게이트는 없다.

2. **확률에 의존하면 안 되는 것만 스크립트가 소유한다.** id 발급, frontmatter와 메타데이터, 세션 바인딩, 원자적 선점, 파일 조립. 이것들은 한 번 틀리면 조용히 틀린 채로 남고 나중에 복구가 어렵다. 그 외의 모든 것은 판단이므로 skill이 기술한다.

3. **커밋 없이 generation을 닫지 않는다.** 이것은 게이트가 아니라 규칙이다. `complete` skill이 지시하고, agent가 `git status --porcelain`으로 확인한다. REAP가 git을 감싸지 않는 이유는 agent가 이미 git을 쓸 수 있기 때문이다 — 감싸면 중복이고, 중복은 언젠가 어긋난다.

4. **공유 맥락은 milestone에 쌓인다.** generation은 맥락을 소비하고 갱신하되, 소유하지 않는다.

5. **도구는 흐름을 막는 대신 사후에 검증한다.** `reap doctor`가 확정적으로 검사할 수 있는 것을 검사하고 보고한다. 고치지 않는다.

6. **검증할 수 없는 것을 검증한 척하지 않는다.** git이 아닌 plan source에는 커밋 규칙이 적용되지 않고, 자유 서식 본문은 검사하지 않는다. 못 하는 검사를 하는 척하는 것이 조용히 통과시키는 것보다 나쁘다.

7. **사람이 적합도를 판정한다.** 정량 지표는 없다. milestone 종료 시 사람의 자연어 피드백이 유일한 신호다.
