## What changed in REAP

v0.17.1 introduced content-type memory tiers and a mandatory reflect-phase pruning policy, but the rule text only reached `reap-guide.md`. Two other carriers kept the old text: the reflect-phase prompt (fixed in v0.17.2, ships with the package) and `genome/evolution.md` (this note's job — REAP never overwrites your genome).

Left unfixed, your project would hold two contradicting instructions:

- `genome/evolution.md` → tiers classified by **lifespan**, update rules are **append-only**
- reflect prompt (v0.17.2) → tiers classified by **content-type**, pruning is **mandatory**

Which one wins is unpredictable, and `reap-guide.md` says the genome is the authoritative source of truth. That is why this note exists.

## Genome immutability — a deliberate, one-time exception

Normally the genome is only modified during `completion --phase adapt`. **This note is an explicit exception, limited to v0.17.2**, because REAP itself shipped the incorrect text and must retract it. Do not treat this as a precedent: future rule changes go through the normal backlog → adapt path.

### 3. Apply the replacement (Branch A, or Branch C after approval)

Rewrite the two sections to match the current rules. Read `~/.reap/reap-guide.md` § Memory for the canonical wording and mirror it. Write in the project's configured language (`config.yml` → `language`). The result must cover:

- **Tiers classified by content-type, not lifespan**, each with its 1-line decision rule:
  - `shortterm.md` — session handoff — "Is this needed right now?"
  - `midterm.md` — ongoing tracks — "Is this an incomplete large track?"
  - `longterm.md` — design lessons — "Does this lesson prevent the next generation from making the same mistake?"
- **The 4-step decision tree**, including step 4: *finished with no special lesson → do not record at all* (lineage and git history preserve it)
- **Per-tier pruning policy**, mandatory during reflect:
  - shortterm — **replace** the previous handoff, never accumulate
  - midterm — on track completion, **promote** key decisions to longterm and **delete** the section
  - longterm — periodically **delete** sections already documented in genome, and lessons that no longer change behavior
- **Bloat thresholds** — longterm ~30~50 lines, midterm ~50~70 lines; exceeding them means pruning was skipped

If your `evolution.md` also has an "Environment Refresh at Completion" section, add that `environment/summary.md` must have superseded content **removed**, and must not accumulate per-generation changelog entries.

### 4. Verify

Re-read the edited sections and confirm: is any tier still described by how long it lives? Is any update rule still append-only with no deletion counterpart? If yes, step 3 is incomplete.

You can also run `reap fix --check` — v0.17.2 adds size warnings for the memory tiers and `environment/summary.md`. Warnings there are informational; they are resolved by the pruning step in your next `completion --phase reflect`, **not by hand-deleting files**.

Run `reap update --mark-migrated`. Skip this if you took Branch C and the user declined.
