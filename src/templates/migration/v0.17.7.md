## 1. `## Repeated Omissions Need a Check` → `### When building a check`

**Add one bullet.** A check can pass while the thing it guards has been deleted.

### If that section looks exactly like this

This is what 0.17.6 and earlier shipped. Compare **including the intro sentence
and every bullet**:

```markdown
### When building a check — make it fail first

If you write a check and immediately see it pass, you do not know whether it catches anything. "The check works" and "the check is inert" look identical.

- Run it against the **broken** state first and confirm the failure. That failure is the evidence the check is real.
- Do the same per assertion — break a known-good value, confirm the failure, restore it (negative test).
- **Record what the check cannot see, alongside its results.** Passing means "no problem within the check's scope". Without a stated limit, the next person trusts it further than it goes.
```

If it matches, **replace it with this and say nothing** — you are restoring the
file to the state it would have had if the project were initialised today, and
asking permission for a no-op is an interruption:

```markdown
### When building a check — make it fail first

If you write a check and immediately see it pass, you do not know whether it catches anything. "The check works" and "the check is inert" look identical.

- Run it against the **broken** state first and confirm the failure. That failure is the evidence the check is real.
- Do the same per assertion — break a known-good value, confirm the failure, restore it (negative test).
- **Record what the check cannot see, alongside its results.** Passing means "no problem within the check's scope". Without a stated limit, the next person trusts it further than it goes.
- **Ask what would still be green if the feature were simply removed.** A suite can assert around a feature — its pure helpers, the order of strings in a file — without anything observing that the feature happens. And if every row of a coverage table shares one premise, adding rows cannot help: the shared premise is the dimension nobody varied.
```

### Why this bullet exists

A generation added a redirect, wrote unit tests for the pure function that
decides it, wrote assertions on the order of two lines in the file that calls
it, and drove a real browser through 27 cases. Everything passed. Deleting the
one call that invokes the feature left **657 unit tests and two gates green**,
and the redirect simply did not happen.

The second half of the bullet is the same failure from the other side. Those 27
browser cases all began *arrive at `/`*, so the entry point was never a
variable — and the one defect a reviewer found in minutes was reachable only
from a different entry point. More rows would not have helped.

## 2. `### Record what kind of evidence you have`

**Add one paragraph** at the end of that section, after the `grep -rn` line.

### If the section ends exactly like this

```markdown
**To write `[ran]`, you must be able to name the command that exercises that item.** If you cannot, it is `[read]`. gen-083 recorded an unverified item as satisfied and the evaluator caught it; the tagging convention created from that lesson then failed **one row over** in gen-084 — the behaviour was correct, but nothing in the gate or the tests exercised it. "It was correct" is not the answer to this problem.

When unsure, run `grep -rn "<functionName>" tests/`. Zero hits means `[read]`.
```

Append this paragraph after it, and say nothing:

```markdown
**`[ran]` goes stale — after changing a value, re-run the sentence that measured it.** A marker beside
a value can at least be grepped; **an artifact has no marker.** So the question after an edit is not
"what sits next to this" but **"which earlier sentence was a measurement of what I just changed"**.
**Do not check by the number alone** — it can coincide, and where it does, checking the number passes
while the claim is false.
```

### Why

A generation corrected a quoted block in its own artifact, then edited the file
that block quoted — and the quote went stale in the same session. The line count
happened to stay the same, so checking the number would have passed while the
quote was wrong.

## If either section is anything else

Your genome has been edited or translated, and this note cannot know which parts
were deliberate. **Show the human the bullet or paragraph being added and ask
before writing.** If they decline, leave the file alone and **do not run
`reap update --mark-migrated`** — leaving it unmarked is what makes this note
come back next session rather than disappearing unapplied.

Translate into whatever language the rest of that file is written in. A rule in
the wrong language is a rule the agent reads past.

## Already there?

If your `evolution.md` already contains both — you initialised recently, or a
previous session applied this — **there is nothing to do and nothing to report.**
